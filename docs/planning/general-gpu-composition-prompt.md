# 通用 GPU 合成实施提示词

日期：2026-10-27。本文是后续开发任务的可复制提示词，不表示运行时已实现。架构、阶段和验收规则分别以[设计](../platform/general-gpu-composition-design.md)和[验收计划](../validations/platform/general-gpu-composition-validation.md)为准，不在此复制一套规格。

## 主提示词

将以下内容作为开发任务提示词使用：

```text
你正在开发 DrawVerse。请按 docs/platform/general-gpu-composition-design.md 和
docs/validations/platform/general-gpu-composition-validation.md，分阶段实现通用 GPU
合成，在保留 CPU 兼容、文档真值和故障恢复的前提下，改善连续绘画、移动图层与
自由变换的实际画面响应。重点验收首个有效位移到内容显示，不能只证明稳定拖动快。

先读当前 AGENTS.md、README.md、上述设计/验收和现有 GPU、移动、变换、任务渲染
入口；检查实际分支、HEAD、工作区差异与已有验证记录。保护其他进行中的改动，
沿用当前有效分支/提交/推送规则，不根据历史记录强制切 master 或重建旧方案。
本任务授权实施；如果调用者明确只要求文档或审查，则服从调用者范围。

职责：
1. Rust 核心保留权威 CPU 文档、笔刷、分页、事务、历史与最终像素提交。
2. paint-render 保留 CPU 参考/后备，并提供设备无关的合成计划与依赖。
3. paint-ffi 只发布版本化、有界、不可变的计划和必要瓦片，不暴露原生 GPU 指针。
4. Qt 窗口渲染设备负责显存、增量上传、多通道合成与直接显示。
5. CPU 后备覆盖能力不足、不支持组合、预算不足和设备故障；显示后备不丢笔、
   不改变文档、不重复提交历史。
6. 现有 paint-ops/paint-gpu 算子继续用于数值任务。正常 GPU 显示不得逐帧走
   GPU 合成→CPU 读回→QImage→Qt 再上传。

先执行 G0：建立当前准确版本的移动和自由变换基线，并写一个真实 Qt 窗口上的
同设备多通道合成与直接显示试验。核实 Qt 最低版本和目标 API，记录格式精度、
设备生命周期、后备条件、预算和技术选型证据。不能以单纹理贴图、独立离屏 wgpu
输出或只生成 PNG 冒充这一步。首选路线不可行时，保留稳定 CPU 默认并提交有证据
的替代方案，不默默退成逐帧读回路径。

随后按 G1→G2→G3→G4→G5 交付，每阶段都必须有可运行纵向成果：
- G1：不可变合成计划、有界瓦片读取、身份/租约/能力协商与取消关闭。
- G2：Normal 栅格、透明度、偏移、隐式白底、自身蒙版，真实增量 GPU 合成及后备。
- G3：移动/自由变换复用已有源，提前准备；目标确认后最新绝对输入直接驱动
  本地几何，不等每次 Actor 回执或16ms合并计时器；快释放与最终主画面原子交接。
- G4：隔离/穿透组、有效祖先与固定蒙版、剪贴和现有混合模式逐组合迁移。
- G5：多文档、浮窗、高DPI、显存压力、设备故障/恢复和支持范围默认启用。

重要不变量：
- CPU 文档真值与已提交结果可独立于 GPU 重建。GPU 预览不能写回替代最终结果。
- 精确复用当前组/蒙版/剪贴、隐式白、线性预乘与显示转换语义；遵守先合成再LOD
  的参考定义，不能把逐层mip或2048代理静默当作精确显示。
- GUI/渲染线程不进行冷盘IO、整图CPU合成或阻塞等待后台/显卡。
- 数据包、瓦片pin、上传暂存、GPU缓存和在途资源都有预算与释放路径。
- 显示可合并，真实笔采样、Begin/End/Cancel和历史命令不得丢弃或越序。
- 不支持显式CPU后备；不能只跳过蒙版或混合模式，也不能任意切开穿透/剪贴闭包。
- 跨窗口不直接复用现有窗口GPU对象；设备epoch变化拒绝旧资源。
- 始终区分核心revision与本地几何序号，迟到回包不能回退显示。
- 关闭交接必须由对应主视图最终权威状态被节点采用证明；概览或任意frameSwapped
  不可替代。保留已有失败与未归因记录，不修改有效断言制造通过。

验证：先按验收计划冻结场景、门槛与计时边界，再运行。复用现有有界观测，记录
输入、目标确认、准备、上传、节点采用与对应帧关联；明确节点采用/提交和物理
屏幕显示不是同一指标。性能阶段不抓图、不逐事件写日志；正确性独立抓图。
先做最小相关核心、ABI和Qt验证，每阶段交付完成相应门禁；需要最终完整验证时
复用 python tools/check.py，失败如实记录，不跳过失败项后报告完整通过。
新增ABI由Rust生成头并检查C/C++静态/动态消费者，文档格式不因显示改动而升版。
运行时交付更新标准 build/bin/Release/drawverse.exe，记录实际构建与后端证据。

每阶段更新验收记录：已支持、CPU后备、未测、失败、性能范围、原始产物位置及
下一步。结束时报告完成阶段、实际用户行为、验证结果和剩余边界。不要只留接口、
计划或“GPU可用”状态就称实现完成；不要承诺未经测量的延迟或全部硬件支持。
```

## 分阶段续接方式

为了控制一次任务的修改范围，可以在主提示词后追加一行；只替换阶段，不复制设计：

```text
本轮范围仅为 G0，完成基线、真实窗口技术验证和选型记录后交付，不提前扩展完整合成器。
```

```text
续接当前已验收阶段，从第一个尚未完成的阶段推进。本轮范围仅为 G1；先核查 G0
的API/精度/直显证据仍适用于当前版本，再实现计划与传输，保持当前默认显示行为。
```

```text
本轮范围为 G2 与 G3。必须形成真实画布中的 Normal/蒙版合成及移动/自由变换
首帧响应闭环；支持矩阵之外保持明确CPU后备，不能提前标记G4或全部通用支持完成。
```

```text
本轮范围为 G4 或 G5（调用时选定一个），按验收矩阵补齐剩余组合或稳定性。
先保留准确基线和未归因失败，按当前有效提交规则交付，不重跑无关性能矩阵。
```

## 任务审查提示词

```text
审查 DrawVerse 当前通用 GPU 合成实现，对照设计与验收计划，以源码、协议和真实
运行证据为准。重点检查：CPU真值是否仍独立、是否暗中逐帧读回再上传、Qt设备与
线程生命周期、瓦片/快照租约是否有界、旧发布是否能覆盖新几何、组/蒙版/剪贴与
LOD是否保持语义、CPU后备是否完整、移动/自由变换首帧是否真正测了内容变化。
检查既有失败和断言是否被保留，区分主视图节点采用、GPU完成与物理显示时延。
只报告可定位的问题、后果和缺失证据；部分阶段通过不得改称全量完成。
```
