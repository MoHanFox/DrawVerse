# 文档工作区与面板列交互（2026-10-09）

本次用户明确要求多个独立文档、画布之间的浮窗标签组合、面板列统一折叠以及直接移动浮窗。只修改 UI：每个文档拥有独立 PaintCoreClient，经既有 C ABI 管理自己的 session/历史/文件任务；不改 Rust 或 ABI。活动文档切换时工具面板与菜单绑定对应客户端，画布本身始终绑定自己的客户端，保留视口与历史。新建/打开添加文档，关闭文档或退出依次处理未保存文档和文件任务，不伪造多文档。

画布与工具面板分开：主工作区始终保留背景色 #17191C 的文档区域；文档全部浮动时工具面板保持原来的侧栏范围。画布只接受其他画布作为标签，主窗文档区上边缘接受画布归位；拖出文档标签或文档浮窗标题进入浮动状态，工具面板不能以画布为停靠对象。工具条仍可以停在任意工具面板两侧。

垂直连接的工具面板构成面板列，只有最上方显示移动/展开收起栏，内部仅显示可拖分隔条。列可整体折叠为图标；每个工具标签组仍可通过面板菜单折叠为标签或关闭。小栏移除关闭按钮。所有组折叠时内容按最小高度连续排列，不分配空白到标签之间；浮动列保留展开尺寸并恢复。

直接拖动实际原生浮窗，鼠标移动时立即更新位置、当前可停靠对象及蓝色预览，不使用替代窗口的拖动截图。拖动列排除自己的所有叶节点作为目标；Escape 取消并恢复原位置/结构，Ctrl/Command 暂停吸附。释放后合并/分割目标或保持浮动。单标签拖出与整列拖动区分处理。

布局 v6 保存工具树与列图标状态，旧 v1–v5 迁移将画布与工具混合树分离，并保持工具组。文档分组是本次运行中的独立真实文档，不把重开布局误当成像素自动恢复。验收覆盖列顶部唯一栏、全部折叠、图标恢复、自己不可接收、画布与工具互拒、留空背景、真实浮窗跟随鼠标/取消/停靠，以及多个文档独立绘画/历史/保存/打开/切换/标签组合/关闭；普通及两倍 DPI、Windows 实窗和完整 tools/check.py。

按用户后续补充，移除顶部画笔选项栏右侧的性能设置和创建面板图标，保留导航菜单中的“编辑 → 性能与暂存盘…”及“工作区 → 自定义面板…”入口。测试从菜单动作打开两个真实对话框并继续验证设置，避免删除入口后无法使用。

后续交互修复以 icon-rail-design.md 为准：删除标签折叠，仅保留整列图标模式；新增侧边临时面板与图标拖出，单画布浮窗合并标题行。
