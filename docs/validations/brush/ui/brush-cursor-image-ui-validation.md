# 半透明图片光标Qt验收

2026-10-17，Windows。对应[Qt设计](../../../brush/ui/brush-cursor-image-ui-design.md)及[原生验收](brush-cursor-image-validation.md)。ABI1.53已被Qt后台实际消费，设置页“光标与预览”新增“半透明图片”、不透明度滑条和数值百分比。默认关闭/25%，范围1–100%，通用复选框/1000ms提示；窄列采用分行布局。无新ABI、state或VBR变化。

全局cursor.image/imageOpacity严格验证，缺失使用false/25；复制、重置、原生规范化与预设交换均不写入这些显示设置。DocumentManager既有偏好同步/单写入者复用新字段，关闭重启保持。图片固定白色及实际基础alpha，当前前景/背景、工具混合不重建图片；实际绘画像素和预览请求保持独立。

后台每轮最多处理一个PNG请求，需求仅当前/在途主副的去重最多4个身份。结果只按仍有效身份采用，当前及在途分别读图，关闭/简化清空Qt需求与结果；副角色要符合复合、双色溢出及工具条件。在途重新打开开关从原捕获身份恢复；失败按身份记录，不随每次鼠标移动反复生成。QML Image关闭全局缓存、隐藏时释放source，仅对256边单位直径图做大小/圆度/旋转及缩放变换，不重复套原始长宽比。几何轮廓可独立关闭，图片未就绪且没有其他定位显示时回退系统十字。

起笔时已有catalog/session锁，原轮廓队列可以更新，但不能同步发图片显示通知触发原生姿态重入；图片更新移到起笔锁释放且drawing已捕获之后。End/Cancel清除在途身份并切回当前需求，旧结果不覆盖其他身份。缺失资源导致准备失败时沿用已有原生最后合法状态恢复；被淘汰身份的图片错误同样丢弃，不强行覆盖已恢复的当前光标。

实际最小结果：

- 新Qt 2项通过：偏好默认/严格类型和有限整数范围/旧配置缺省/失败原子保持、复制重置、无预设或VBR污染/无真实笔刷预览通知；真实QML复选框、白色PNG全覆盖/孔洞、73%叠加、图片独立轮廓、角度/圆度、CapsLock和吸色接管、简化/仅悬停、参数切换及开关重开。
- 实际绘画中主副不同图片各自捕获；切换两角色为程序笔尖仍显示捕获图，关闭复合或图片后再打开恢复原图；取消后只显示当前资源。源资源缺失触发原生错误并恢复合法定义，过期错误不替换当前光标。通过真实DocumentManager新建另一文档检验偏好双向同步，全部关闭/销毁后重新创建客户端检验磁盘重启保存。
- 实际窗口截图前后对照，白色图片使棋盘格对应像素亮度提高，当前画布revision/历史在显示设置操作间不变。最终`brush-cursor-image-ui.png`人工查看：透明孔洞、白色叠加及窄列百分比控件可见。截图为显示层，不进入文档像素或导出。
- 环境倍率1：新2项加旧图片轮廓/复合捕获/全局偏好/数位笔悬停4项，共6功能用例通过（含init/cleanup为8 passed）。环境倍率2：新2项再通过（含init/cleanup为4 passed），有独立实际窗口截图；这是Qt环境倍率，不能宣称所有实体设备DPI/驱动认证。
- 最终Windows Release、生成头检查及4项C/C++ static/shared ABI通过。Rust没有修改，未重复无关Rust整套或Qt全套。用户自行进行整体Windows硬件手感验收，跨平台后置。

验收修正记录：新测试最初误用不存在的三参数newDocument、混合auto类型声明和setEyedropperTool，分别改为真实建层/删背景流程、分开声明和activate接口后编译通过。副资源清空原来传空字符串，按既有格式改为null。缺失资源原先断言图片错误必然常驻，但原生准备会先恢复合法定义，改为验证实际错误与恢复；两个独立客户端原先被误认为自动同步，改用应用真实DocumentManager路径验证。没有通过放宽生产校验或删除原需求来规避失败。
