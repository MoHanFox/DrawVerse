# Brush Interaction Baseline — Issue #2-A

## 基线、目的与结论边界

关联 [Issue #2](https://github.com/MoHanFox/DrawVerse/issues/2) 的④吸色、⑤大小/流量/不透明度/压感设置；⑥仅做有限方向姿态观察。本阶段只调查，没有性能优化，没有更改防抖、通知策略、缓存、画质、线程调度、Rust ABI、依赖或锁文件。

- 预审与实际产品基线：`7f5bd4c3acd507fc24069350a7a66a276b992976`，执行前 fetch 的 `upstream/develop` 与之相同，无需混入上游更新。
- 测量代码提交：`e7950d754d7b374e76ac5cc4be6e67aca23856bf`。所有正式进程的 raw.json / invocation.json 均记录该 SHA，且可执行文件 SHA256 一致。报告在后续独立文档提交中补齐；文档提交不是另一份产品测量。
- 本地分支：`feature/issue-2a-brush-interaction-baseline`；仅操作 Fork。英文目录入口仍指向同一个 Fork 工作区。
- Windows 10 19045、Ryzen 7 5800H（8核16线程）、MSVC x64 19.43.34809、Windows SDK 10.0.22621.0、Rust 1.99.1、Qt 6.8.3 MSVC2022 x64、CMake 4.4.4、VS 自带 Ninja 1.12.1、Python 3.10.8；复用既有安装，未升级或重装。
- Release，真实可见 Windows 窗口。初始化日志实际选择 **AMD Radeon(TM) Graphics，vendor 0x1002/device 0x1638/flags 0x0**，Prefer software device=0；初始化后接口为 `QSGRendererInterface::Direct3D11`。不是仅根据 `QSG_RHI_BACKEND` 宣称启用硬件。未发现需要展开软件后端对照的证据，因此没有软件全矩阵。

本机条件下确认存在“异色比同色工作更多”和“规模增加后的后续快照工作增长”。**尚未取得可确认的、与报告者实际环境等价的明显卡顿复现**；这不等于 Issue 不存在。未建立输入到屏幕呈现延迟指标，也没有新增性能通过阈值。

## 场景、数据与隔离

每档3个独立进程，进程内按表顺序执行固定21行；每行51次（首次1次单列，正常重复50次统计）。另对256档 A0/A1/A2 关闭诊断重复3进程。共9进程、6,885个场景采样（包括空闲、辅助 setter 和方向观察，不能全部称为鼠标点击）。每个正式采样均保留，没有过滤异常尾部。

- 原生 Main.qml，1280×800 **逻辑像素**；报告 DPR=1、逻辑 DPI=96，物理 DPI 保留于 raw.json；512×384白色画布，`actualSize()`、zoom=1。默认停靠布局，当前预设始终为 round-pressure。A0为画笔工具空闲，A1/A2切为专用吸色工具；侧面板布局保持，工具栏按产品原行为改变。A0用于背景活动观察，不能将不同工具的差值解释为因果。
- 计时外用合法绘画 API 生成半径48、无大小/流量/不透明度压感、flow/opacity=1的实心红蓝色块，中心(128,192)/(384,192)；先等待历史提交并核对两个实际显示快照像素。诊断开启前完成绘制、撤销蓝块、重做蓝块验证。
- 默认库为4个内置预设；256档保留4个内置，反复 select(round-pressure) + `BrushLibrary::saveCopy("issue2a-NNN")` 生成252个合法副本，最后选回 round-pressure。名称/参数生成规则固定，API内部UUID可变，无外部笔刷或图片资源。**合成库仅观察数量效应，不代表学生真实笔刷库。**
- A1重复吸取红色，初始颜色红；A2从蓝开始，红/蓝交替，匹配51次、目标125ms离散节奏。使用发往原生 QQuickWindow 的**合成 Qt 鼠标事件**，不是实体输入或OS SendInput。
- A3大小使用现有设置页 `settingsBrushSizeSliderTrack`，流量/不透明度用现有顶部 QML slider。大小设置页 category=0；没有复制一套替代控件。相同位置(.3)点击为同值对照；离散在轨道归一化.3/.7间交替；连续拖动从.3向.7单向发送51个位置，目标16ms，停止时真实 Release 另计同步耗时。每个场景只操作一个参数。大小使用产品原指数映射，数值取决于真实控件；flow/opacity用原步长，部分微小位移量化为同值，仍计入尝试与完成。
- A4明确切换大小压感（设置页category=1）、流量压感、不透明度压感（顶部checkbox），每次一个布尔开关。相同值 setter 行明确标作**辅助 C++ 对照**；它不替代真实checkbox交互，不等于实体压感测试。
- A6方向控制 direction、roundness=.4；固定方向/慢速/近静止位移步长分别为1、0.1、0.0001逻辑px，dy=dx/2。只有有限合成鼠标悬停，不涉及驱动、WinTab、Windows Ink或滤波修改。
- 每个进程的配置、workspace、brush-resources、TEMP/TMP、JSON/截图位于它的独立 run-N 目录。正式运行关闭Qt图形磁盘缓存，QML缓存显式指向run目录；不读入或删除用户笔刷配置/绘画文件。原始结果均在忽略目录 `artifacts/issue-2a/`。

## 时钟、指标与关联规则

1. `steady_clock` 单调纳秒；同步段从构造/发送窗口事件前至事件返回及即时getter校验后。它包括工具端轻量验证开销，**不是纯 setter 耗时，也不是端到端输入/显示延迟**。不含 QTest 的等候、截图或写盘。
2. 离散行在同步段外按125ms目标节奏让事件循环运行，并检查持久化定时器不活跃、相关信号已静默80ms，最多5秒。连续行每次同步段外运行事件循环约16ms；Release后同样观察收尾。表中 tail 是**含人为节奏/静默条件的观察时间**，不是后台处理时间。状态不要求新 frameChanged。
3. 8ms PreciseTimer GUI心跳只代理事件循环响应性；Windows实际心跳通常约11ms。不用QTRY、固定等候或进程总时间充当处理时间。报告未保存逐心跳时间戳，因此不能把某个心跳最大间隔严格归因到某条span。
4. 每条span有单调起点、duration、线程、id/parent和operation（行号×1000+样本号）。同线程嵌套span是inclusive，不相加；后台span可以与GUI并行，也不相加。计时段内诊断工具不截图、不逐事件打印/同步写盘；产品原有的后台偏好保存行为保留并观测。原始记录上限200,000，正式6次均未溢出；结束前关闭采集并等待已进入的scope返回。
5. GUI延迟回调的operation是**当时的时间上下文**，连续拖动时不代表最初触发输入。偏好保存队列额外捕获提交时operation和入队时间，`preferences.queue_us` 对应该Qt queued job；`worker.saveBrushPreferences` 包括当次poll，BUSY后另一次poll不能误算成原调用的同步时间。
6. 目录准备以真实 preparation票据连接 GUI request 与 worker完成观察。request时间在prepare调用返回后，complete在worker轮询确认/等价检查后、INI同步之前；包含轮询/调度，是**完成观察上界**，不是Rust纯计算时间。未匹配票据单列。没有可靠状态→呈现关联，显示延迟为**未测**。
7. 每次实际参数变化由颜色、radius、flow、opacity及三个压感值的前后比较计算；通知独立计数。近静止角度不是配置变化，因此A6参数变更计数为0。样本始终保留，包括同值、慢样本、失败或超时；本次正式数据全部状态校验成功。
8. p50/p95用nearest-rank，正常段N=50；首次单值不算p95。span表若N<20只作为该次个别观察，不外推稳定分位数。

在已有英文仓库入口运行，不重新安装环境。先激活既有MSVC环境并临时加入工具路径：

```powershell
$vs = & "${env:ProgramFiles(x86)}/Microsoft Visual Studio/Installer/vswhere.exe" -latest -products '*' -property installationPath

python tools/measure_brush_interaction.py build/bin/Release/qt_brush_interaction_baseline.exe artifacts/issue-2a/default --trace
```

## 分层结论与下一步

**已确认行为**：同色吸色/同值控件没有颜色或设置变更通知；异色、离散参数及压感布尔切换均产生真实变更。离散阶段每次变更都有后续持久化；连续阶段观察到防抖后的末尾工作。首次与正常重复分开保存，窗口实际使用硬件D3D11。

**有测量支持的热点**：256项下，异色后的GUI snapshotObject构造显著多于默认4项；该工作发生在后续持久化，不应归入setBrushColor同步时间。目录同步也随规模增长；A2没有新目录准备票据，所以不能归咎于Rust目录编译。后台保存调用的耗时随规模增加，但它与GUI并行，本次Qt job排队很短。没有证据支持把所有开销归为快照“字节编码”、某一个signal或Rust。

**尚未验证的假设**：真实图像笔尖/纹理与复杂预设是否将这些后续工作放大到明显卡顿；多文档偏好广播的影响；QML布局/其他通知在个别同步尾部中的占比；实体输入中参数变化、persistencePending与姿态回退是否会共同造成⑥抽搐。当前只有调用链与规模相关证据，未做逐项消融，不证明报告者卡顿的因果链，也不根据模型归因。

下一阶段最多两个修复候选（需独立任务验证，不在本阶段实施）：

1. **颜色专属持久化与执行目录失效的职责边界**：A2改变颜色而不改变可执行预设，却触发随256项增长的快照对象构造/目录同步；优先用真实库确认是否应只处理颜色相关状态。此为可定位候选，不是已经证实的Issue④根因。
2. **参数提交后的完整模型快照/目录准备成本**：离散参数和压力开关暴露连续拖动可能掩盖的末尾工作；先在真实预设下进一步拆分对象构造、编码和准备，再评估方案。不要以延长防抖、减通知或增加缓存替代原因验证。

未覆盖真实学生笔刷、图像资源/纹理、实体手绘板、跨机器分布、端到端输入/呈现延迟。上述合成结果不可外推成真实使用环境结论。本阶段完成基线即停止，不进入优化。
