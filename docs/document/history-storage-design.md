# 大笔触历史记录：设计与验收

问题：预览 dab 在首次碰触每个瓦片时，用 2 × 64KiB + 元数据估算撤销成本，超过 64MiB 就撤回整个笔触。空白 before 与共享 after 也被完整计账；该历史保留预算不应阻止正常涂画。

方案比较：增大固定内存上限只能推迟失败；超预算不记录历史会丢失整笔撤销；允许最新命令无限超限会失去资源控制。本轮采用分层历史存储，小命令维持 Arc 快照快速路径，大命令无损编码，超过内存预算时落到受限临时文件。内存预算继续有效，当前整笔仍可一次撤销/重做。文档 live 瓦片、输入段工作量与磁盘实际容量仍有真实资源限制，这一模块不声称已经实现整个文档的磁盘分页。

编码按瓦片逐块执行，浮点通道以 IEEE 位模式 little endian 保存，重复像素游程压缩，压缩不合算时存原始像素；不存在量化或色彩空间转换。编码 writer 内存达到历史预算后迁移至 RAII 临时文件，避免先构建无限大 byte Vec。临时文件仅存内部命令，不是用户绘画文件。磁盘历史总预算 4GiB，超过时淘汰最旧历史；一个命令超过磁盘预算或写入失败才返回实际存储错误。文件关闭/历史淘汰时自动删除。核心使用项目已锁定的 tempfile，跨平台且不依赖 Qt。

编码成功后才提交并淘汰旧历史；失败保留旧历史、回滚当前事务。undo/redo 完整读取并验证命令之后才修改文档，读取失败不得破坏现有像素或历史栈。大笔触仍是一条命令。结构变化准备存储后再修改层结构。编码/磁盘 IO 在 Rust 调用线程执行；Qt 经现有后台 actor 提交与完成，不在 UI 主线程做编码或磁盘读取。小笔触性能路径不变。

4GiB 是已保留磁盘历史的预算。为了先准备成功再淘汰旧记录，写入下一条命令时会暂时额外占用这一条的空间；系统磁盘空间不足会明确返回存储错误。使用系统临时目录，正常关闭/淘汰自动清理，进程被强杀后的遗留文件清扫与可配置暂存盘属于后续完善。校验码用于检测内部文件的意外损坏，不作为插件安全认证机制。

正在进行的笔触 before 受 live 文档瓦片数量上限约束，外部只读快照仍须及时释放，不纳入历史 budget；这不是整个进程 RAM 的绝对上限。解码 transient 命令可能暂时使用两份瓦片像素，但在修改文档之前完整校验，避免 IO 中途失败造成部分撤销。

验收：超过旧 64MiB 门槛的一笔完整涂画可完成/撤销/重做；低预算下实测压缩内存与磁盘路径，浮点 bit 精确往返、删除层、redo 分支、最旧命令淘汰、取消与文件损坏读失败的原子性。Qt 连续输入跨旧上限且不出现错误，undo/redo 正确。完整 check、原生目录重建，并重跑先前绘画性能基准验证小笔触没有回退。Python 插件最后实施。
