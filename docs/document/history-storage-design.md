# 大笔触历史记录：设计与验收

问题：预览 dab 在首次碰触每个瓦片时，用 2 × 64KiB + 元数据估算撤销成本，超过 64MiB 就撤回整个笔触。空白 before 与共享 after 也被完整计账；该历史保留预算不应阻止正常涂画。

方案比较：增大固定内存上限只能推迟失败；超预算不记录历史会丢失整笔撤销；允许最新命令无限超限会失去资源控制。本轮采用分层历史存储，小命令维持 Arc 快照快速路径，大命令无损编码，超过内存预算时落到受限临时文件。内存预算继续有效，当前整笔仍可一次撤销/重做。文档 live 瓦片、输入段工作量与磁盘实际容量仍有真实资源限制，这一模块不声称已经实现整个文档的磁盘分页。

编码按瓦片逐块执行，浮点通道以 IEEE 位模式 little endian 保存，重复像素游程压缩，压缩不合算时存原始像素；不存在量化或色彩空间转换。编码 writer 内存达到历史预算后迁移至 RAII 临时文件，避免先构建无限大 byte Vec。临时文件仅存内部命令，不是用户绘画文件。磁盘历史总预算 4GiB，超过时淘汰最旧历史；一个命令超过磁盘预算或写入失败才返回实际存储错误。文件关闭/历史淘汰时自动删除。核心使用项目已锁定的 tempfile，跨平台且不依赖 Qt。

编码成功后才提交并淘汰旧历史；失败保留旧历史、回滚当前事务。undo/redo 完整读取并验证命令之后才修改文档，读取失败不得破坏现有像素或历史栈。大笔触仍是一条命令。结构变化准备存储后再修改层结构。编码/磁盘 IO 在 Rust 调用线程执行；Qt 经现有后台 actor 提交与完成，不在 UI 主线程做编码或磁盘读取。小笔触性能路径不变。

4GiB 是已保留磁盘历史的预算。为了先准备成功再淘汰旧记录，写入下一条命令时会暂时额外占用这一条的空间；系统磁盘空间不足会明确返回存储错误。使用系统临时目录，正常关闭/淘汰自动清理，进程被强杀后的遗留文件清扫与可配置暂存盘属于后续完善。校验码用于检测内部文件的意外损坏，不作为插件安全认证机制。

正在进行的笔触 before 受 live 文档瓦片数量上限约束，外部只读快照仍须及时释放，不纳入历史 budget；这不是整个进程 RAM 的绝对上限。解码 transient 命令可能暂时使用两份瓦片像素，但在修改文档之前完整校验，避免 IO 中途失败造成部分撤销。

验收：超过旧 64MiB 门槛的一笔完整涂画可完成/撤销/重做；低预算下实测压缩内存与磁盘路径，浮点 bit 精确往返、删除层、redo 分支、最旧命令淘汰、取消与文件损坏读失败的原子性。Qt 连续输入跨旧上限且不出现错误，undo/redo 正确。完整 check、原生目录重建，并重跑先前绘画性能基准验证小笔触没有回退。Python 插件最后实施。

## 后续分页结果历史

已完成的大液化现在优先保留受文档 PagePool 管理的结果引用，按元数据预算计账，像素由共享驻留/暂存预算控制；未托管或元数据超预算仍回退编码。上述编码格式与普通笔触/其他命令的行为保持。详细职责和边界见 [长任务资源预算](../tools/long-task-resource-budget-design.md#2026-10-21-已完成大液化的结果历史)。

## 共享结果引用扩展

自由变换、整图水平/垂直翻转、置入图层栅格化的 LayerEdit，以及油漆桶的 Stroke，接入同一 prepare_result_in。所有原始/结果瓦片（含置入源）必须属于当前 PagePool，且图层/选区/瓦片引用元数据在预算内；否则保留原编码后备。小命令仍 Inline。普通绘画、结构、置入确认等其他命令保持原路径。

LayerEdit 的选区按保留的步骤、点、遮罩和空间索引内存保守计账，不再把压缩文本长度当作遮罩内存，也不为计账编码整块遮罩。共享 Arc 的引用可能保守重复计账，避免低估。热历史复用原始结果身份，冷历史仍验证换页负载并按预算读取；IO失败仍不修改现有文档、历史或修订。没有取消校验，也不承诺冷磁盘零耗时。

## 2026-10-21 冷页历史校验与恢复分离

内联/分页历史恢复前，按不可变Tile身份去重，驻留数据保持原校验语义；冷页只读取原编码字节并校验写入时的完整checksum，不解码像素、不加入或触碰LRU。Page只会由已验证像素编码产生，外部/损坏数据无法通过checksum冒充原页。真正显示/编辑时仍走完整read/decode和驻留预算。两侧损坏仍在历史栈变化之前失败，直接跳转整体回滚保持。Encoded命令仍完整解码校验，磁盘冷数据仍可能造成IO等待，不能称任意大小历史恒定时间。


## 2026-10-22 单次历史跳转共享冷页校验

直接历史跳转在私有事务内持有 HistoryVerification，Inline/Paged 命令共用不可变 Tile ID 的已校验集合。相邻结果保留的同一瓦片在本次请求只读取校验一次；Encoded 负载仍各自完整解码校验。只在校验成功后记录身份，不缓存像素，也不改变LRU。请求结束即释放集合，下次 undo/redo/跳转重新验证，不能跨请求以身份代替磁盘完整性检查。

最多记忆65536个身份；达到该数后未记忆项继续原完整校验，不拒绝编辑或缩短历史。它是可退化的临时元数据缓存，不是画布/任务容量上限。直接跳转仍逐命令应用私有状态，只发布最终状态；任何后续负载失败保留原层引用/选区/修订/dirty和两侧历史栈。没有承诺冷物理磁盘即时跳转，也没有新增持久化格式或ABI。


## 2026-10-30：统一按数据选择历史存储

参考本地 `D:/PhotoCraft/photocraft-main/crates/ops/src/lib.rs` 与
`crates/engine/src/history_select_cmds.rs` 的不可变共享结果、一次发布思想，独立实现；未复制代码。
PhotoCraft 保存 Arc<Document> 整体状态，DrawVerse 保留现有命令差分和 PagePool，避免每次小笔触复制整文档瓦片引用表。
这是存储入口重构，不是完整快照系统迁移。

`Document::commit_with_action` 不再用 UI action 白名单决定是否复用结果，统一交给
`StoredCommand::prepare_result_in` 按命令数据、PagePool 所属关系和元数据预算选择。
普通画笔、橡皮、湿混/涂抹的 Stroke 包括小命令均优先保存不可变 before/after 瓦片引用；
原 LayerEdit/Canvas 大结果同样复用，旋转自然进入 Canvas 路径。结构命令继续原 Inline/Encoded 路径。

Stroke 元数据每项计 `size_of::<TileChange>() + 2*256`，另加128字节；
所有引用必须属于当前 PagePool，引用表超预算或未托管时回退原无损编码。
像素由共享 PagePool 驻留/暂存预算管理，不另编码一份历史像素。历史条数、分支和淘汰规则保持。
这会使部分压缩率极高的命令使用更多历史元数据，却避免恢复时重新解码和产生新瓦片身份。

冷页仍逐请求校验、跳转内有界去重，不能跨请求跳过损坏检查。Encoded 故障测试显式选择编码后备，
共享路径另有不写历史文件、100次小笔触保留/跳转/新分支及 Arc 身份验证。
没有 ABI、文档格式或持久化历史格式变化，也没有新增固定画布大小限制。
