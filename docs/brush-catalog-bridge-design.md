# Qt 草稿与原生笔刷修订桥

Qt 保留控件草稿与全局显示/工具偏好，Rust 验证并拥有已编译库修订。设置草稿提交通过新增异步 prepare-state ABI：仅复制有界 JSON 并返回序号，解析/编译在独立、全进程共享的2线程元数据池运行，不与等待修订的文档执行池竞争。

每次准备生成独立不可变结果；开始笔触捕获准确的准备结果，即使之后提交新设置仍保持该修订。文档 Begin 在 Rust 串行执行时等准备完成，后续 Move/End 保持原队列顺序；Qt 不增加绘画队列，不阻塞 GUI，也不因参数正在编译而丢掉起笔。任务异常/验证失败明确返回错误，不能替换成默认笔刷。

目录保留最近64个准备记录供查询；在途笔触已经持有记录 Arc，不受记录裁剪或库销毁影响。元数据任务队列32项、单请求2MiB。过期记录明确 NOT_FOUND。同步目录读取发布最新已成功结果，失败保持上一合法目录；读写仍使用准确 revision 屏障。

迁移支持旧 v1 和 v2 参数状态，内置身份由 Rust 确定，失败保持原持久文件。原生状态只包含预设/选择；临时工具尺寸、颜色、光标与布局由 Qt 独立保存。规范化状态读取供 Qt 接受有效修订，并在后台保存；过时结果不得覆盖新草稿。

Qt 接入采用共享、独立于文档生命周期的库连接；每个文档开始笔触引用同一个已提交修订。后台预览使用隔离修订/会话，避免预览选择改变活动文档的预设。全量状态迁移先支持程序预设；含图片资源的状态必须走后续有资源身份的编解码器，当前不允许恢复时清除图片资源。

验收：v1/v2迁移/非法整包原子性、准备失败/异常、起笔紧跟设置变更、多文档共享、库销毁/记录裁剪后笔触继续、快速提交后旧结果不覆盖新结果、预览与文档使用同一有效参数、后台保存错误保留旧配置。
