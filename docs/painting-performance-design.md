# 绘画性能回退：诊断与修复设计

先复现当前版本，再以相同压感输入、同一画布/物理视口比较修复前后。暂停新功能，保留文件保存、撤销、数位板及工作区行为。

已识别的热点：CPU Renderer 每个修订遍历整幅物理视口（含透明区域），对放大后重复采样的像素重复做 sRGB powf；每帧重新合成所有已分配瓦片。Qt 每次笔触元数据发布重赋 layers 并用同一个 stateChanged 通知模型，可能导致图层 Repeater 重建；画布因此也收到与视口几何无关的刷新。

方案比较：降低绘画分辨率/更新频率实现简单，但损害画质与响应；立即加 GPU 改动与验证范围过大。本轮保持画质、帧输出和 ABI，通过稀疏输出及有界瓦片合成缓存减少重复工作，Qt 按实际变化通知模型。

CPU 输出初始化为透明，仅遍历有贡献的屏幕瓦片矩形。输出坐标映射提前按轴计算，保持既有全局对齐 LOD 和像素中心采样；每个源 mip 像素只编码一次，再重用显示字节。每视口独立 CachedCpuRenderer，根据有序源瓦片 Weak 引用、图层不透明度及 LOD 判断复用；弱引用避免保留整份旧文档及地址复用。只缓存完整、已验证瓦片，有明确字节上限，取消检查不改变历史/修订屏障。CpuRenderer 仍提供无缓存 CPU 后端，不引入 Qt/GPU 依赖。

每槽缓存计账负载上限 96 MiB，包括线性/显示 mip、源身份和条目数据；四槽最多 384 MiB，另有容器/分配器开销，不是整个进程的内存上限。视口、LOD、格式或尺寸变化时裁剪不再使用的条目；未命中且放不下时直接计算并输出。Weak 不保留瓦片的像素载荷，且 Arc::make_mut 在写入时分离弱身份，因此同一笔触中间写入也能正确失效。缓存锁只在渲染线程持有，不在文档 actor 或 UI 上清空/等待。

Qt 图层模型采用独立 layersChanged，只在层定义/顺序/属性变化时发出；其他 UI 状态通知按值变化，画布帧与文档几何独立。保留刚提交修改的未保存保护。

验证：可复现 release 渲染基准、真实 QML 窗口的定时压感笔触/帧间隔/事件循环延迟记录；与优化前文件逐项对比。Rust 比较原密集采样参考和稀疏/缓存输出（含分数ROI、越界、各LOD、透明、层属性、撤销/取消/代际）。Qt 验证绘画不重建图层委托，改层仍刷新，保存保护仍有效。跑统一 check 和原生启动目录 build/qt 更新。基准结果是本机固定负载，不声称达到所有设备 <8ms / 120fps。
