# 输入分页数值与预算验收

2026-10-16，Windows。对应[设计](brush-input-paging-design.md)第1阶段。本轮交付可执行的原始输入段分页调度器和Document共用预算权重，不是画布分页入口；Document像素/起收笔重放及Actor分块仍未接，真实Qt单次64px密集图片输入限制仍存在，不宣称已经修复。

调度器保留原始输入段的主副独立步长/余量、同位置第二优先及静止压力的副后主顺序、累计弧长/方向和现有设备插值（包括原有时间戳语义）。prepare_page只生成有界事件并保留原游标，成功后adopt；过期或异实例页拒绝。保存段和小游标而非整笔印章数组。每页不超过原8192/8M预算或8192事件；单印章超页、最多4096滤波段/131072实际估算印章/512M估算访问等边界明确拒绝。

最小验证结果：

- `paint-core --lib input_page` 9项通过：8项调度事务/几何用例及1项原预算对照。不同页事件上限1/2/7/31/8192、主或独立双流、原始短段/折返/静止压力、倾斜/跨角旋转/缺失设备通道/时间与按钮逐事件完全等于独立保留的旧Document循环参考；不插终点，不让分页成为新输入点。
- 真实密集64px数值调度超过一页后完整发出所有印章；空计划、4096个无印章段、单印章/总访问/实际散布计数、极小步长导致计数溢出、非法坐标/压力/单调时间/步长/预算、缩小预算失败不前进、过期和异实例采用拒绝通过。未建立全部印章的事件数组。
- Document的原预算分支提取成主副每操作权重，并继续用于旧同步入口。4尺寸×2资源组合×3算子×4双笔刷分支×3湿混工作量×10主计数×5副计数，共14400组与保留的旧公式核对，接受/拒绝分类保持，含usize极值；旧8M/8192限制没有放宽。
- `paint-core --lib wet_dual_` 10项、`--lib taper` 11项通过（包含交叉筛选的起收笔湿混组合项，不能把二者说成21个互不重叠用例），真实像素/载色/原子回滚等旧行为保持。
- paint-core全目标Clippy `-D warnings`通过；Windows Release、cbindgen生成头一致性及4项C/C++ static/shared ABI通过。无C ABI、state或VBR变化。

只改Rust内核及预算计算，未运行无关Qt整套或跨平台验收；Windows整体设备/手感验收由用户进行。相关本机日志为`artifacts/brush-input-paging-kernel-{tests,wet,taper,clippy,release,abi}.log`，不入库。首轮测试代码的Rust小数字面量缺少整数部分导致编译失败，已修正测试代码后完成上述检查。

下一阶段必须把事件页真正应用于Document，并处理原始滤波一次采用、起收笔活动尾回放预算、单历史/失败取消和准确载色，再接Actor公平调度、完成序列与End/Cancel。不能仅将调度器存在视为用户问题解决。
