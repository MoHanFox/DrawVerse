# 套索绘画性能修复（2026-10-11）

问题：框选或套索选好后，用画笔绘画和橡皮擦除都需要选区覆盖。原实现对每个笔尖像素反复扫描套索边段、求距离及 4×4 采样；连续笔尖大量重叠，同一选区覆盖重复计算。纵向索引减少了边数，但没有移出绘画热循环。

方案：选区共用按文档像素行计算覆盖的接口；多边形按行排序交点后成对填充，AA 批量计算四条子行，羽化只检查可能进入羽化带的边段并使用平方距离。沿用奇偶填充、对称 smoothstep 羽化和原组合算式，不简化用户路径。加入独立于快照/历史/IO 的有界覆盖缓存，按当前不可变选区身份切换失效，笔尖行查一次缓存后直接读覆盖；矩形/椭圆和套索共用缓存。不会分配整幅画布，未选择的笔刷保持原快速路径。缓存限制明确，图层位移按文档坐标查询，取消/撤销/载入不留下旧覆盖。

前后用同一个实际绘画基准测无选区、矩形、4096 点套索、羽化套索和连续重画；冷缓存也计入，不只报告热缓存。测试扫描线覆盖与既有标量算法一致，包含凹形、自交、水平/垂直/小数边界、组合、反选、AA 和羽化；覆盖缓存命中/逐出/身份失效、图层位移/蒙版/撤销和保存往返回归。Qt 验证 4096 点套索提交后实际笔触的异步帧更新、边缘限制、事件循环和撤销后继续绘画，复跑鼠标/数位板与 DPI 回归。

验收：矩形/椭圆框选、密集套索及羽化套索分别测画笔和橡皮；橡皮在预先绘制的真实像素上执行。每轮输出独立耗时，首轮计冷缓存，后续轮计重用。逐像素回归覆盖画笔和橡皮、偏移跨缓存块、清除/撤销/重做及加载失效。缓存最多 4096 个 64 像素行块（覆盖载荷 1 MiB，另加有界索引开销），不随画布尺寸增长。完整 tools/check.py 和原生交互回归，通过后部署并 commit/push。无 ABI/文件格式变更。

完整验证暴露 Qt 用例默认设置写入真实用户目录，可能受用户配置、权限及剩余空间影响。测试将默认 QSettings 的用户/系统作用域重定向至用例生命周期内的临时目录，每例清空默认设置；显式设置文件仍正常测试读写/往返，产品配置行为不变。验收必须验证临时目录有效和真实 sync 成功，不能吞掉保存失败。

两倍 DPI 全量运行还暴露并排蒙版用例在 delegate 创建后立即读取尚未完成的 Row 布局（单独重跑通过）。保留原几何断言，改为有界等待布局条件，随后继续真实点击与像素断言。
