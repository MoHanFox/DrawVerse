# GPU 算子与可恢复弹性液化

2026-10-19，功能分支 `feat/wgpu-support`。验收记录见 [验收](../validations/tools/liquify-gpu-operators-validation.md)。

## 边界与行为

文档、输入顺序、资源预算、历史、分页与原子发布仍由 CPU 管理。新增无 UI 的算子请求/结果和 CPU 参考执行器；wgpu 只负责批量数值计算，失败时用同一不可变输入执行 CPU，不发布半个 GPU 结果。不改变 VBR 或工作像素线性预乘 RGBA32F。

液化会话保存不可变原图和有符号坐标的弹性位移网格。画布只裁剪显示，不裁剪网格编辑域；从画布外拖入、反向推移和重建可以重新采样原图。网格节点使用平滑径向核、局部刚度和逆向位移组合；密度控制核的软硬，强度/设备压力控制力，四工具共用场采样和重映射。

交互只更新笔刷附近节点并重采样脏区域，使用较粗的预览像素步长；完成时从同一最终网格对受影响区域（包括画布外瓦片）进行全分辨率逆向采样，未变形区域保持原图，数学上等价于对全图执行恒等/变形映射。采用结果前检查瓦片/历史预算；完成失败保留可取消、可重试的会话。预览不反复变形已采样像素。

算子分为弹性场更新、像素重映射和紧凑块预览采样。CPU/GPU 共用输入计划、资源准备、插值/坐标规范、结果校验和提交；后端保留融合与批量执行空间，禁止逐像素 GPU 提交。GPU 设备由 FFI 运行时装配，paint-core 不管理设备。硬件选择位于设置的性能页，提供 CPU、自动以及实际枚举的硬件，保存全局偏好；未支持或失败有真实状态说明。

PhotoCraft 参考仓库为 `storytold/photocraft`，核对提交 `4d4de453058759d944731722c3e7c5f9524cf27a` 的 `crates/algo/src/liquify.rs`（MIT / Apache-2.0）。参考其不可变源、位移组合、预览与最终插值分离的思路；本实现独立编写，不复制 UI、品牌或着色器，不据此推断 Photoshop 私有实现。

## 算子与采样规范

- `paint-ops` 定义 `ElasticOp`、`RemapOp` 与 `RemapBlocks`，承载网格、只读源、覆盖率、输出区域和预览步长，负责验证、CPU 参考执行与上传布局。`paint-gpu` 只依赖该契约；仅开发测试依赖 `paint-core` 验证真实文档组合。
- 权威位移网格为间隔 2/4/8/16 px 的 f32 二分量、有符号稀疏网格；大笔刷约每半径 64 节点，小笔刷需要更细间距时先插值细化旧场，局部历史保存前后间距。推拉采用 `D_new(p)=s(p)+D_old(p+s(p))`；膨大/扭曲先生成逆向局部坐标增量，再共用组合。四邻域的局部刚度按权重混入；重建直接使场回归零，低于阈值清零以恢复原图身份。
- 平滑核为 `1-t²(3-2t)`，密度调节核内区，强度乘笔压。按运动距离细分输入；halo 按实际逆向位移与刚度模板求界，不重复准备整个笔刷宽度的外圈。
- 大笔刷预览采用 2 px（半径 ≥64 px）或 4 px（半径 ≥256 px）像素块及双线性源采样；CPU/GPU 每块复用一次场/源采样，无选区时只读回每块一个颜色及恒等标志，再复用原始像素展开，保留恒等区逐像素精度；有选区时使用完整输出并保留逐像素混合。预览只物化与画布相交的像素瓦片，画布外场仍完整保留，小笔刷使用 1 px 双线性采样。完成使用 1 px 输出及 Catmull-Rom 三次源采样，预乘结果钳制合法范围，恒定邻域保持逐位精确。预览与完成共用同一权威网格，避免两套网格累积漂移；完成阶段不创造额外网格细节。
- CPU/GPU 共用事务、准备、坐标与采样约定，Rust/WGSL 各保留一个小型数值实现，并用数值回归约束。它们不逐位相同：GPU 浮点融合和超越函数有误差，验收阈值为 `1e-4`；同一后端的历史保存实际结果，因此撤销/重做仍精确。

## 资源、故障与设置

单输入仍有 8M 工作预算，计量节点更新次数加一次预览像素面积，而非把每个细分步都按全像素预览计费；场最多 8192 个 64×64 节点瓦片，输出最多 8192 像素瓦片，提交与预览每批最多 128 个像素瓦片。每个请求最多 8M 样本，源暂存最多 2048 个像素瓦片，原始冷页逐个读取，避免长期 pin 大批源页。上述计数分别约束工作，不代表整体内存仅占单个预算；源、编码数据、输出与驱动暂存可同时存在。GPU 另按设备存储绑定大小拒绝超额请求并回退 CPU。

wgpu 固定 `26.0.1`（项目 MSRV 1.85），启用 Vulkan / DX12 / Metal，设备和管线按执行器保留。位移请求与结果仍逐批上传/读回，文档与历史由 CPU 掌握；不可变源瓦片按不可变像素身份缓存于独立 GPU 绑定。CPU 会话缓存与 GPU 源槽分别最多 2048 个瓦片（各 128 MiB）；CPU 缓存复制原图数值，不 pin 原图冷页；GPU 只保留弱身份，不延长已结束会话的 CPU 像素寿命。源槽满则清空索引并重新填充，不无限增长。原图不超过 2048 个瓦片时在进入液化时预热，较大图像按请求惰性缓存。上传/输出/读回缓冲区按需增长并复用。设备丢失、读回超时（5 s）、验证或执行失败使该执行器切换 CPU，并保留可查询原因；结果验证和历史准备完成后才原子采用文档。算子执行不持有 ABI 注册表锁。

设置默认自动选择 GPU（auto），已保存的显式 CPU 选择继续有效，支持自动与枚举硬件，保存 `performance/computeDevice`，后端工作线程负责枚举与偏好同步；活动笔触、液化和变换期间不可切换。新建/打开保留会话执行器。完成时显示不确定进度条，仅表示正在计算，不显示伪造的百分比。

边界：此次将液化接入 GPU 算子，其他工具/笔刷维持原执行；接口可后续扩展。GPU 画布合成、笔刷计算迁移、智能对象持久液化网格、全局多文档 GPU 缓存和跨平台硬件验收均未在本次实现。

## 2026-10-19 大笔刷交互修订

用户实机反馈 2000 px 拖拽粘滞、GPU 占用偏高。此次默认偏好改为 auto，已有显式 CPU 偏好仍保留。交互网格按笔刷半径选 2/4/8/16 px 间距（半径方向约 64 个节点），同一会话只在需要更小笔刷时细化已有场；历史同时保存网格间距，避免撤销后坐标解释变化。网格细化先准备候选，预算失败不采用；最终仍从不可变原图全像素重采样。

大笔刷预览改为 4 px 块，GPU 每块执行一次场和颜色采样；无选区时只返回紧凑颜色，alpha=-1 是明确的恒等标志，CPU 复制不可变源像素，不用统一块颜色覆盖恒等区；选区保留完整逐像素混合。源数值在不可变对象构造时校验一次，CPU 会话和 GPU 源槽复用同一身份，不重复转换/校验/上传整图。复用 GPU 上传/输出/读回缓冲区，避免逐 f32 打包及每批分配。输入最多保留一个在途更新和一个待处理最新位置，完成反馈后继续；抬笔必须冲刷末位置后结束历史，避免输入积压。必要检查限于算子/液化/设置目标回归和同机 2000 px 性能对比，不扩大全量。

## 实施前验收条件

- CPU 路径独立可用；GPU 功能不改变原有工具/笔刷执行。
- 四液化工具、平滑过渡、密度/强度/压力、负坐标、图层偏移、选区/蒙版/锁正常。
- 推出画布后从外向内拖回、反向操作和重建恢复；取消与局部/文档撤销重做保持像素和场。
- 预览与最终采样分离，最终不采用低分辨率预览像素；预算和历史故障不部分提交。
- CPU/GPU 算子数值对照、真实硬件执行、故障回退及硬件选择持久化；无硬件时明确记录。
- Rust 目标回归、格式/Clippy、生成头、C/C++ ABI、Windows Release 和 Qt 性能设置/液化入口；完整检查仍为 `python tools/check.py`，未执行项明确列出。
