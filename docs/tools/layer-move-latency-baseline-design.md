# 主线 C1 — Layer Move Latency Baseline

本轮只观察已有移动策略，基线为 B2 合并后的 develop。独立按需 Qt Test 宿主使用真实 CanvasItem、原生可见窗口和 Qt 合成鼠标事件；不加入默认构建或 CTest 性能门禁。Python 只负责独立进程、隔离目录和结果汇总，不访问 UI 线程。

## 场景与验收条件

S1 为 1024² 全幅红色 Normal 栅格层；S2 为 4096² 同类图层；S3 为 4096² Normal 组内全幅红色子层，带链接的黑色实心圆孔蒙版；S4 为相同子层的有效未链接蒙版。白色背景显露位移和孔洞。非空范围不是稀疏小笔划。每场景至少三次独立进程，每进程先切移动工具立即拖动，再在现有准备资产上传批次已提交后拖动；回退场景只称首次/后续。每拖动 120 个位置，单次 QTimer 目标间隔 8ms，独立记录实际发送间隔、同步处理段和最终整数位移。

使用已有 InteractionTrace 的有界内存记录器，默认关闭，不新增采集框架。GUI 提交序列、元数据接纳、worker 解码、预览接收和 render-thread 采用的 revision/source 分开记录；render 只读同步阶段已有不可变包。上传计数表示 Qt 记录资源更新操作的批次，不表示 GPU fence 完成。计时段不抓图、不输出逐事件日志、不同步写盘。核心内部排队与 CPU 执行若无可靠边界则保持未测，不把发布观察时间冒充纯计算时间。

完成以 GUI 元数据中的位移、历史增量、关闭状态和对应完整 frame revision 为证据；不使用任意 frameSwapped 关联输入。截图/像素、撤销重做和取消验证在独立正确性阶段。记录超时、失败、溢出及未完成；心跳仅是事件循环代理。不得改动 16ms 合并计时器、2048 源上限、资格、预热、线程或像素算法。

详细运行命令、每次结果及限制放入对应验收报告；原始产物放忽略目录 artifacts/issue-2-main-c1/。没有物理设备或显示端到端测量，不据此声称学生手感已修复。
