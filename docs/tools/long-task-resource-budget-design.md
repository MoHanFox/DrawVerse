# 长任务资源预算与大画布

## 问题与约束

2026-10-21 用户明确：切笔刷卡顿可随时发生；液化的 source staging budget 是单次会话多次操作后报错，不能将两者直接归因为历史记录。

液化把最多 128 个输出瓦片的包围框按最大绝对位移向四周扩张，可能暂存超过 2048 个源瓦片。另有最终输出 8192 瓦片的固定限制；这约为 3355 万像素，不适合大范围处理 8K/16K 文档。

预算应限制同时驻留的数据和单次提交量；可拆分的工作不能因总量超过单批预算直接失败。保留文档逻辑瓦片、内存驻留、磁盘空间、坐标合法性限制；不承诺物理资源无限。

以 8192²/16384² 为例，DrawVerse 每像素 4 个 f32 通道，单份完整原始像素分别约 1GiB/4GiB。它们不应一次放进 GPU 或暂存 Vec；实际物理开销还取决于稀疏瓦片、共享、压缩、历史、图层和换页。更大的图需要更多总存储与完成时间，预算机制的目标是让工作可持续推进，而不是把总计算成本消除。

| 范围 | 应负责的限制 | 本轮状态 |
| --- | --- | --- |
| GPU/CPU 一次重采样提交 | 输出批量、源暂存与算子网格 | 自动拆批，极端单元按需 CPU 采样 |
| 结果与源图的总规模 | 文档逻辑瓦片、磁盘容量 | 仍保留，输出不再另受 8192 瓦片限制 |
| 会话位移场和一次输入段 | 网格存储与输入工作量 | 现有保护仍在，未全部改为分页/可恢复续算 |
| 历史保存与恢复 | 状态数量、共享结果、冷热存储 | 大液化保留分页结果引用；其他类型保留编码/换页 |

## 实施

- `paint-ops` 提供与文档无关的自适应批次规划：从常规批量开始，不适合暂存则折半，直到可提交或只剩一个单元。单元仍超限交给调用方的流式后备。
- 重采样算子提供可失败的按需源像素访问接口，复用同一双线性/三次插值与选区混合公式。后备路径只缓存有限的原始瓦片，不降低最终质量。
- 液化使用带符号位移极值估算源范围，并包含原输出坐标以保留零位移、选区和原像素语义。暂存前规划，不先分配再报错。常规批次仍可走 GPU，单瓦片超限走 CPU 按需访问。
- 输出瓦片上限改为文档配额，逐批物化；源图像与位移场仍不可变/会话内保留。候选完整成功后才发布；失败不更改当前图层和历史。
- 后续变换、滤镜等长任务可使用同一规划函数及采样接口；本轮不宣称它们已全部迁移。

## 历史架构调查

PhotoCraft 本地参考版本 `d95fdf3181c01ad41e95456091a394b105a9afb2`：`crates/ops/src/lib.rs` 的 `HistoryState` 保存 `Arc<Document>`，undo/redo 交换快照引用；`crates/engine/src/history_select_cmds.rs` 私有遍历后只恢复一次状态；`crates/engine/src/jobs.rs` 使用 COW 快照、工作线程、进度和取消，成功后提交一个历史步骤，失败丢弃候选。历史有状态数/共享瓦片内存预算和旧记录淘汰，并非无资源上限。

DrawVerse 已有私有历史跳转、一次修订/发布和瓦片换页；但 `history/mod.rs::StoredCommand::Encoded` 每次恢复均经 `history_storage.rs::decode_in` 解码并新建瓦片身份。全局已完成液化历史与会话内部位移场历史是两条路径；会话内部还会读取字段负载。不能把所有历史延迟归结为重复执行液化，当前恢复没有重新运行液化算法。

改进方向是按预算保留不可变结果/瓦片身份，热历史直接恢复，冷记录后台读取，渲染按真实变更刷新；必须同时验证损坏读取的回滚、redo 分支、换页配额与真实 UI 回执。不能靠无界缓存或取消校验掩盖耗时。

Adobe 公开文档可用于确认用户可调的历史、缓存、内存和暂存盘机制，不能证明 Photoshop 私有历史容器、快照布局、线程或液化网格精度。此次网络访问未获得可核验正文，故这里不将上述私有实现归于 Photoshop。

验收见 [资源预算验收](../validations/tools/long-task-resource-budget-validation.md)。

## 2026-10-21 已完成大液化的结果历史

后续已扩展到完成自由变换、整图翻转、置入图层栅格化及油漆桶，见[共享历史结果](../document/history-storage-design.md#共享结果引用扩展)。LayerEdit保留所有目标原始/结果及选区，置入源也检查PagePool归属；图层和选区实际保留内存计入元数据预算。其余工作任务与液化会话位移字段历史仍保留各自路径。

新增 StoredCommand::prepare_result_in 作为长任务结果存储入口。当前接入完成液化的 Stroke 结果；较小命令保持 Inline，原始像素估算超过历史预算时，只有所有 before/after 瓦片都属于当前 PagePool、且引用元数据估算能放进历史预算，才保存 Paged 命令。否则仍使用原先有损坏检查的 Encoded 后备。不能把未托管像素视为零成本引用。

Paged 保留 Arc<Tile> 而非像素 pin，复制变化表不复制 RGBA；历史预算计入变化表和每个引用的保守 Tile/Page/cache 元数据余量。实际像素由现有文档 max_resident_tiles 和 max_scratch_bytes 控制，所有历史元数据仍参与总预算及历史步数淘汰。释放历史记录会释放无人使用的身份和换页块。不新设第二份解码缓存，也不额外编码一份相同像素。

恢复沿用完整瓦片验证，再原子修改历史和像素。热记录读取已有像素，不创建新瓦片身份；冷页仍需磁盘读取/校验，失败保持当前状态。history_disk_bytes 仍统计独立编码历史文件，分页像素的暂存使用 storage_stats 的 scratch 项，不能将前者为零解释为无需磁盘。

此入口可由其他产生瓦片差异的长任务复用，但本轮仅接液化完成记录；自由变换 LayerEdit、普通笔触和液化会话内字段历史未改。全局暂存空间仍有限，也尚未实现暂存不足时主动淘汰旧历史后重试。大图与很多记录超出物理存储时仍可能失败；不能宣称任意 16K 多层历史均可常驻或瞬时切换。

## 液化会话位移场历史分块读写

会话字段仍由共享Payload承担内存/磁盘后备、校验和、长度与生命周期；没有额外常驻缓存。局部字段编码保持原count/key/两侧presence/4096个二维f32的小端布局，每块以固定4KiB暂存缓冲流式写入和读取，消除每个通道一次动态Read/Write调用。每个字段仍只包含4096个向量，原有限值和位移绝对值上限不变。

撤销/重做只为要恢复的一侧分配向量数组；另一侧不保留数组，但仍逐值验证，并由Payload检查完整长度、结尾与校验和。任何一侧无效、截断或IO失败都不发布候选；直接历史跳转仍沿用原回滚边界。位移场精度、画布外内容、原像素身份、历史分支/步数/磁盘上限、ABI和GPU执行范围不变。

此项只减少会话字段编解码和临时分配成本，未把字段迁移为PagePool结果引用，也没有消除跨越多条差异记录的读取。热OS缓存下磁盘后备的测量不能称为物理磁盘冷读或UI响应时间。验收见资源预算验收末节。

## 2026-10-22 液化会话不可变字段引用

会话历史每步的字段预算仍为 max_history_bytes / max_history_commands。在此预算内，直接保存变化坐标及两侧不可变 Arc<Vec<[f32; 2]>>，恢复时只复制引用；计账保守包含每侧实际 Vec 容量、Arc/Vec 元数据及变化表，重复共享也逐项收费。这样整段 undo+redo 的字段引用总量受原步数与预算限制，没有额外热缓存。预算不够时保持既有 Payload 编码与磁盘后备，不降低网格精度或删掉历史步骤。

引用候选捕获前验证两侧长度和所有位移的有限性/范围，后续编辑仍创建新数组或遵循 Arc 写时复制，不能修改历史保留的内容。编码后备恢复仍完整检查两侧值、长度与校验和。引用与编码可以混合在同一会话，直接跳转保持单次修订与失败回滚、redo 分支和取消语义。此优化仅针对会话位移场；像素结果沿用原 PagePool 路径，ABI/state/文件格式不变。

验收应覆盖引用身份、修改隔离、预算临界与真实磁盘后备、混合步骤/细化/画布外恢复、损坏回滚以及软件/D3D11历史显示。计时分别报告内存字段与OS热缓存磁盘后备，不称为UI或物理冷盘速度；完整8K/16K及实体持续手感保持待验。

## 液化历史直接跳转的单份候选

多步会话跳转不应逐步复制完整位移表和图层瓦片表。以当前不可变状态建立一份私有字段/图层候选，按历史顺序应用每条差异；完整读取和校验全部成功后，才一次更新当前状态、历史游标和修订。任何中间字段读取失败直接丢弃候选，当前像素、字段、undo/redo、dirty与revision保持。逐步undo/redo与直接跳转复用同一个步骤恢复函数，不重新执行液化或像素采样。

这只消除与跨越步数相乘的容器复制/中间dirty更新；冷记录仍完整读取校验，不跳过被后续步骤覆盖的历史损坏。无新增缓存或预算，位移场和像素结果引用机制保持。
