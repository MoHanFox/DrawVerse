# 菜单分类与图层批量操作修复

## 范围

重建“图像 → 调整 / 画布旋转”和“滤镜 → 模糊”的悬停侧向子菜单。共享菜单项控制行高、文字、勾选与小箭头；子菜单属于同一菜单链，避让屏幕边缘，保持在浮动面板之上。未实现的图像效果仍明确禁用。

图层多选删除、排序与归组在 Rust 中一次校验、一次提交、一次撤销。输入有界为 1–4096 个唯一 ID；祖先与后代同时选择时只操作祖先子树。移动保持原有相对堆叠顺序，蒙版跟随所有者；拒绝循环、锁定、无效 ID 等操作时文档与历史均不改变；删除全部图层按后续[空图层栈契约](empty-layer-stack-design.md)允许，仍只提交一次可撤销历史。ABI 1.13 新增批量接口，原接口兼容保留。

选择中包含组时，删除入口统一弹出“仅删除组，保留内部图层 / 删除组及全部图层 / 取消”。确认绑定原文档代次与当时选择；仅删组移除组属性及组蒙版，提升直接子节点到原父组，不烘焙组效果。没有组的选中图层正常删除。批量删除历史保存移除节点像素与前后结构，兼容磁盘暂存，撤销完整恢复。

拖入新位置后，若上方同级邻居为剪贴图层，移动的节点自动加入该剪贴链（存在下方基底时）；不插断上方原有链。原位置失去基底的剪贴层仍释放剪贴。批量移动中的每个根节点遵循相同规则。

首次打开图层面板的卡顿须检查真实加载路径。重内容采用异步创建，并避免在 GUI 线程生成缩略图或一次实例化整个图层列表。保持已有后台缩略图、可见行请求与独立缩略图通知。

## 验收

- Qt Test 真实悬停打开两类图像子菜单与模糊子菜单；小箭头、紧凑行高、菜单链关闭、浮窗置顶及屏幕边界验证。
- Rust / ABI 验证非连续多选删除与排序、组及后代去重、仅删组含蒙版、剪贴链继承、锁定/循环失败原子性、最后像素层删除到空栈的撤销/重做，以及一次撤销/重做和磁盘历史恢复。
- Qt Test 验证选择保持、批量拖放载荷、两种组删除与取消、旧文档确认拒绝；首次打开大量图层时事件循环仍响应且只创建可见行。
- 完整运行 `python tools/check.py`，构建部署应用；验证后提交并推送 `origin/master`。
