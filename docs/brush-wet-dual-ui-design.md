# 湿混双色 Qt 组合入口

依赖ABI1.52/WET_DUAL_COLOR/state19/VBR1.23。Qt只镜像、校验和传递参数，继续使用Rust准备与实际绘画，不复制混色算法。开启湿混和双色双笔刷时，设置器原子加入wetMix.dualColor=independent-carriers-v1；此标记在关闭湿混/双色后保留。老配置字节保持，未标记的活动组合在restore/import时拒绝，不静默迁移。未知标记/null/类型错误或state<19均拒绝，失败不修改当前目录或重置基准。

保存、原生目录采用、独立resetState、保存副本、重启与VBR import/export完整镜像新策略；behavior16/wet-dual-color和最高state19在完整关闭值下仍保持。新库包与准备入口只走明确wet_dual导出，启动检查ABI>=1.52及能力位。原ABR来源保留策略不变。

手动载色捕获当前准确预设票据、尺寸、前景和背景，两描述符在后台调用原子双载色入口；clean仍清洗整工具，Busy阻止并发修改。主文档共享WetTool，自动预览继续独立工具/会话，不消耗真实载色。状态检查使用双角色info。按钮在双色活动时显示“载入双颜色”，说明第二色由双色页背景/前景选择决定；共享湿混比例适用于两角色，但两载色独立。

自动预览state19通过新prepare完整执行，显示固定白色和正常工具模式，保留原alpha；颜色变化不使预览失效。双色湿混仍只用于画笔，涂抹和橡皮的现有拒绝保持，不伪装支持。不得恢复用户取消的试画。

验收：模型双向启用/关闭标记、错误/降级拒绝与目录原子性、独立复制/重置/重开；真实Qt设置页操作/双颜色手动装载捕获/Busy和clean、实际双色区域和第二笔保色、在途改色/预设不改变捕获、像素与undo/redo；白色预览及载色隔离；真实VBR新目录导入/重开后绘画、关闭值/基准及已有图像资源往返。最小Windows Release/ABI和相关Qt回归，跨平台后置。原输入框偶发问题如重现需记录与定位，不能通过无差别重复测试掩盖。

验收期间确认的既有执行边界：密集图片双色湿混在单次64px输入可能超过核心8M估算工作预算，明确错误且整笔回滚。当前端到端交换用例按连续8px输入测试同一完整轨迹；这不证明大跨度输入已支持。后续需在Rust执行/Actor层增加保持印章次序、动态时间和事务语义的分块调度，不能提高预算或丢弃输入冒充修复。
