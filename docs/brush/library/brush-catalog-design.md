# Rust 笔刷库权威模型

图片资源接入前，将可验证的预设模型集中到 Rust。`BrushSettings` 只包含预设参数和不可变覆盖资源，排除前景色、工具临时大小、工具模式与光标偏好。`BrushPreset` 在创建/编辑时验证、编译程序，再生成不可变修订；笔触可保留旧修订，不受后续选择/编辑/删除影响。

`BrushCatalog` 管理顺序、活动 ID、内置身份、名称、编辑、副本、删除和整批导入；首期上限1024预设。兼容四个旧内置别名和原有参数；自定义 ID 使用非零小写 UUID。批次先验证全部身份/容量/定义，成功才发布；ID 冲突明确拒绝，交换导入层按已有副本策略提供新的 UUID，不能悄悄覆盖。

库持有的图片 mip 默认预算128MiB，可设置更小的预算；共享同一 Arc 资源只计一次，导入与编辑均在提交前检查。原生资源池接入后还需把在途笔触及已移除资源快照纳入整个应用的统一预算，本阶段不将库预算当作进程总内存保证。

Rust 库本阶段先建立可执行模型和回归；随后接独立生命周期的原生库 ABI 与 paint-io 资源存储，Qt 模型逐步成为草稿/元数据镜像。原生库不能绑定第一张文档的生命周期；关闭该文档时仍应供其他文档使用。持久化与导入任务在后台执行，GUI 不复制图片绘画算法，也不保存运行中的压力/载色状态。

验收：默认预设兼容、参数/名称/身份拒绝、编辑新修订与旧快照稳定、活动选择/删除保护/副本、批量失败不改动顺序/修订/选择、容量预算、图片资源在快照中保持存活。UI 接入前不宣称 Qt 库已完成迁移。
