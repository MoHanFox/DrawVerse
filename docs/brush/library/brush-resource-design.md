# 图片笔尖持久资源层

Rust paint-io 管理内容寻址的 PNG 资源。ID 是完整 PNG 字节的 SHA-256（小写64位十六进制），文件为资源目录中的 `<id>.png`；引用不携带开发机路径。VBR 原资源按原字节保存并校验，用户图片转换为标准灰度8位覆盖后保存。SHA使用固定版本 RustCrypto sha2 0.10.9，见 [官方文档](https://docs.rs/sha2/0.10.9/sha2/)。

解析前检查压缩字节上限128MiB，PNG解码器限制4096边长、128MiB解码分配。8/16位灰度、灰度alpha以及实际灰度RGB/RGBA可作为覆盖；白色乘alpha为覆盖，不进行显示色彩转换。16位量化到现有8位内核时提供明确标记。用户导入另可选择alpha或反向亮度，不能把ABR反向灰度解释传播到标准资源。

资源缓存用Weak引用，活跃笔触/预设持有Arc；加载串行检查实际活跃mip驻留（默认128MiB、可降低），在像素解码和mip分配前检查新增预算。同资源复用同Arc；失效项清理，目录资源最多4096个。已捕获覆盖不受外部文件修改影响；冷加载重新检查完整哈希，错误明确拒绝。

用户图片规范化时需先在独立解码预算内取得覆盖与canonical PNG身份，才能正确识别不同编码但相同覆盖的重复图片；因此该路径先检查解码预算，再在mip分配前检查新增驻留预算。标准资源已知ID，可在像素解码前检查驻留预算。拒绝APNG及资源文件符号链接。

保存只追加不可变内容文件，用同目录临时文件和不覆盖的原子提交；已存在同ID文件必须校验，禁止覆盖损坏内容。失败/取消不发布缓存或残缺文件。资源目录本身不执行脚本，不按资源ID解压路径。整包导入还需在VBR层先验证全包再发布库；本资源层不把单文件成功当成整包成功。

本阶段建立可执行IO与预算层；下一阶段接原生库的资源身份、持久状态、图片UI、VBR与ABR。旧准备记录需要在图片接入时处理不用修订的强资源保留，不能将64条元数据记录当成无界图片缓存。

验收：已知SHA向量、8/16位灰度/alpha转换、彩色误用拒绝、标准/反向/alpha导入、预算在分配前拒绝/共享去重/释放后恢复、文件往返与独立源、错误哈希/路径/损坏PNG、取消不留下文件、活跃Arc不可变、并发同ID保存一致。
