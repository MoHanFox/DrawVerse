# 快捷键光标稳定与鼠标笔触恢复

## 2026-10-22：复用空格的即时事件状态路径

本节取代下文早期轮询主导方案。Space、Ctrl、Alt键事件只更新各自按下状态，统一调用轻量 `applyShortcutCursor` 同步Item/原生光标与QML通知；不查询笔尖姿态、不等待轮询、不读取另一把键的modifier。按键状态getter只读已发布快照。Hover、TabletMove和Release的modifier不再重写快捷键显示，避免驱动省略modifier或迟到的旧modifier冲掉键盘状态。Press仍允许提供首次手势的modifier；移动/绘制/取色按原手势判定，不修改工具和历史语义。

16ms物理键检查仅恢复丢失键事件（持续两次松开后清除）；仅状态变化时调用同一个轻量发布函数，不逐帧覆盖原生光标，不与笔尖姿态轮询合并。连续Hover不能重启并推迟此定时器。键盘事件正常到达时Ctrl/Alt与Space相同，在当前事件内完成显示更新；不得用QTRY等待掩盖正常键事件需要下一帧的问题。

验收：画笔/橡皮/涂抹与套索Space逐事件同步，Ctrl/Alt连续8轮及漏/迟到Tablet modifier不闪回，快捷键更新不改变笔尖几何；原物理按键无Qt键事件、丢失Release、取色/移动手势与异常离笔保持。

2026-10-22，用户反馈按住 Ctrl 或 Alt 悬停时画笔轮廓与临时移动/吸色光标来回闪烁，并可进一步进入无法继续绘制的工具冲突；鼠标长时间绘制后也会出现画布不更新，但保存重开能看到已提交笔触。

Alt/Ctrl 状态此前有两个不一致来源：键盘事件维护 Ctrl， TabletMove/Release 又按每条事件的 modifiers 重写 Alt。WinTab 和 Windows Ink 的部分移动事件会省略当前快捷键位；窗口失活还会直接清空 Ctrl。修复后，输入事件只负责锁存已出现的工具快捷键，明确清除仅来自对应 KeyRelease 或窗口激活/失活时的系统键盘状态；按下时使用事件与系统状态的并集，避免先落到错误工具。

系统键盘查询在按键刚释放时可能短暂保留旧值，因此只有 Press 允许使用其作为缺失 modifier 的兜底。Move、Release 和 TabletRelease 严格采用事件自身 modifier；否则 KeyRelease 已清掉状态后，紧随其后的 Release/手绘板移动会把旧值重新锁存，表现为松开 Alt/Ctrl 后光标不恢复并污染后续笔输入。

菜单焦点或浮窗切换还可能吞掉 KeyRelease，使本地锁存值没有事件可清。Alt/Ctrl 任一激活时启动 16ms 短轮询，Windows 直接使用 `GetAsyncKeyState` 读取左右 Ctrl/VK_MENU 的当前物理状态，只有连续两次读到已松开才清除并刷新原生/画笔光标；按键仍按住时轮询保持激活，不会在多源 Hover 之间来回切换。轮询在两键都释放后立即停止。

光标显示本身按 PhotoCraft 的即时模式处理：画布指针在内时每 16ms 以当前物理键态重算并应用 Item 与原生窗口光标，而不是由单条 Hover/Tablet 事件的 modifier 增量改写。WinTab 或 Quick 某条事件漏带 Alt/Ctrl 不再影响显示；手势进入哪条工具路径仍只看按下那一刻的 modifier，避免绘制中误切工具。

快捷键轮询只重算光标形状与可见性，不复用 `refreshBrushCursor()` 的笔尖姿态读取。笔尖轮廓的半径/角度/圆度只由真实 Tablet/Hover 样本更新，避免异步姿态尚未就绪时每帧退回默认姿态造成移动闪烁；Caps Lock 的精确十字路径不经过姿态读取，因此天然稳定。

鼠标绘画与手绘笔共用幂等笔触状态：重复 Press 不丢弃已接受的 `m_stroke`，Move/Release 以本地 stroke 或 `PaintCoreClient::drawing()` 任一为准确认活动笔触，失去抓取时也能取消客户端仍在进行的笔触。此前的本地 false/客户端 true 分裂会让后续 Press 被永久拒绝。

普通画笔开始时清除遗留常驻预览，元数据确认液化、移动或变换全部结束后也发布清除，避免旧 GPU 预览继续遮住已经提交的新笔触。

本修复不改变光标几何、绘画算法、ABI、state 或文件格式。

## 2026-10-22：快捷键显示快照与QML通知

光标可见性getter不再自行读取物理键态，统一使用最近一次光标刷新采样的快捷键快照。16ms轮询先记录上一帧可见性，再采样当前物理键态、应用原生光标并比较可见性，保证Alt前后原生光标同为Blank时仍发送QML通知。此前getter在比较前后均读取当前物理状态，无法发现只有物理按键改变的可见性变化，导致QML笔尖与吸色十字滞留。所有同次刷新中的显示判断共享同一快照，笔尖姿态仍只由完整笔尖刷新更新，手势按下判定保持。

## 2026-10-22：元数据发布失败后的重试

后台按精确 publication 分次读取图层、选区、历史、变换与已提交笔触回执；任一次读取都可能因 actor 发布新版本而返回 BUSY。`metadataPending` 只能在全部读取成功、即将发送 metadata 信号时置位。若在最后的回执读取前置位，BUSY 分支没有发送信号，也就没有 GUI 回执清除标记，随后 poll 永久提前返回，像素帧和编辑状态一起停止更新，而内核绘制与保存仍正常。

最小验收沿用真实窗口测试：连续笔触期间持续提交移动样本，结束后校验历史、最新帧与真实显示像素，再完成液化/变换取消并继续绘制；复用快捷键、重复 Press、离笔与图层移动专项。并发用例覆盖完整链路，不宣称每次都命中回执读取之间的竞态窗口。ABI、绘画算法与文件格式保持。

## 2026-10-30：鼠标窗口光标恢复

CanvasItem 的鼠标光标原来仅由 Qt Quick 命中更新，窗口原生光标的显式同步只用于数位笔。窗口光标被恢复为箭头时，Quick 仍可能缓存同一 CanvasItem；再次设置相同 Blank 不会修复窗口值。用户同时报告无选区时箭头不隐藏及 Space 不切手形，因此修复必须覆盖鼠标路径，不能只归因选区菜单覆盖层。

统一窗口同步函数由即时光标刷新及既有16ms快捷键恢复轮询调用。鼠标仅在所属活动窗口、可见可用的交互画布悬停时同步；数位笔保留原所有权。自由变换控制层继续决定手柄光标，Space导航除外。仅在窗口与请求形状不同时写入，不新增轮询、不重发工具通知。离开画布由Quick正常命中恢复面板光标。选区右键监听层使用无光标的Item/TapHandler，归其菜单功能实现所有，不用全局覆盖光标掩盖该层。

验收：有/无选区的画笔、橡皮、涂抹、吸色，在画布请求Blank不变而窗口被恢复Arrow的条件下，鼠标移动及既有轮询均能恢复Blank；Space立即OpenHand，真实鼠标拖动平移、释放恢复且历史不变；Ctrl临时移动、移出画布Arrow保持。数位笔所有权/丢失快捷键释放及变换控制层原回归保持。该反例验证状态恢复，不冒充用户实体操作触发点的完整归因。
