# 湿混双色的双载色事务

前置起收笔 Qt 已完成。本阶段建立工具所有的双载色状态，随后接 Document 双色贡献与 IO/原生/Qt；不以状态容器完成代替实际湿混双色绘画。

主、第二印章必须使用独立二维载体：主从前景色自动载入，第二从已捕获的第二颜色自动载入（使用背景色开关由起笔定义决定）。采用相同 WetSettings，但各自重采样尺寸、拾色、消耗和路径位置；第二流不得消耗主流的载色，单流频率变化不能推进另一载体。实际贡献仍按既有双色隔离整笔场重算，不能把两场预先混色后当成普通湿混笔。

新增 Rust WetInk，包含必需主载体和可选第二载体，最多两个现有64阶网格；for_stroke 在私有副本上按角色重配置、自动清洗和装载，两端全部成功才返回。关闭自动清洗/载色时按角色保留原墨量，切换尺寸重采样并重置路径，不把 load 改变重新乘到保留墨上。新第二角色从透明开始。仍使用现有单载体合法尺寸域1–512，超界明确拒绝；后续实际相对尺寸接入需同时核对其最大边界，不能静默裁剪。

WetTool/WetLease 以完整 WetInk 为事务单位，单个独占租约覆盖两角色。新 snapshot_ink/retained_ink/commit_ink 接口完整捕获、采用；取消/Busy/验证失败不改变任一角色。清洗同时清洗现有两角色；新双角色手动装载原子更新两者。旧 snapshot/retained/reload/commit 继续操作主载体并保留未操作的第二载体，避免旧入口无意丢失副载色。单载体旧行为不变，无预设、文档历史或跨会话数据写入。

验收：不同色/不同尺寸、真实二维拾色和距离消耗按角色独立，对照两个单载体；完整角色/关闭保留/自动清洗载色与路径重置，两个角色准备第二项失败不发布；租约跨克隆 Busy/取消/双角色成功采用、旧主接口保留副载色、清洗两者。现有真实两笔、跨文档所有权、失败回滚及湿混像素回归保持。仅 Windows 最小验证；不解除现有 Document/IO/Qt 的湿混双色保护，无 ABI 或格式变化。
