# 大目录切换与起笔延迟

## 2026-10-21：真实资源目录回传重建

用户补充切换卡顿随时出现，与是否液化没有必然联系。用本机 INI 和 `brush-resources` 的隔离副本（489 个预设、约 2MB 偏好）复现：直接 select 约 5–8ms，后续原生目录回传在 GUI 线程调用完整 restore，约 350–410ms，事件心跳出现数百毫秒停顿。

根因是三个预设的原生状态保留显式默认 pressureDynamics，而 Qt 的 canonicalPressure 会省略相同默认对象。仅按字段结构比较，导致语义未变仍恢复全部预设、重置基线和 QML 行。提高资源上限不能修复这一问题。

`BrushLibrary::equivalentCatalogState` 对已验证的恒等笔压曲线统一比较；较高的已知合法 schema 与当前字段含义相同时无需重建。非默认曲线、选中项、组织、资源或其他参数的真实差异仍进入完整校验/恢复，低版本非法字段不走等价路径。预览令牌与 UI 行保持。

后台 `pollBrushState` 捕获同一准备票据对应的不可变 submitted 数据，先在工作线程做等价比较，仅真实规范化差异或失败回传 GUI。票据检查、失败回退与偏好保存保持原流程；不在后台访问 QObject 模型。直接调用 applyNativeCatalog 也共用同一比较规则。

复测入口：`qt_workflow_tests liveBrushSelectionWithLargePreferences`，设置 `DRAWVERSE_BRUSH_REPRO_SETTINGS` 为隔离 INI 路径，其同级需有资源目录；用例再次复制配置及资源，不修改原件。不设置环境变量时跳过该手动实机数据用例。确定性回归使用合成默认曲线，覆盖真实曲线修改和非法状态拒绝。

详见 [验收](../../../validations/brush/performance/brush-library-switch-latency-validation.md)。这不等同于已解决所有笔刷预览、冷资源、跨文档全量偏好广播与持续输入成本。

2026-10-19。用户反馈导入约400项/32MB后切换和起笔短时强烈卡顿。公开148项ABR样本导入三次形成448项，用真实Main窗口记录首次/重复切换、同步起笔和GUI心跳；该样本不等于用户大包，不能据此宣称完全复现。

减少已知重复工作：Qt仅在实际变更后重建完整偏好/执行目录JSON，同一偏好再次同步时直接沿用准确准备票据；原生后台对“只改selected”的同能力准备复用上一份已成功、不可变目录中的Arc预设与资源，仅校验并切换选择。其他字段任何变化、无成功基线、跨能力或旧票据已退休均走原有完整验证与编译，不减少资源/来源检查，不让失败草稿成为基线。基线使用Weak，避免延长冷票据资源生命周期。

最小验证：Qt448项前后计时、真实绘画/资源往返和多文档偏好；Rust比较准备前后预设Arc身份、修改参数不复用、非法选择保持原目录及旧票据冷重建。记录实际边界，用户原包手感仍需复核。

2026-10-21 追加：旧选择路径调用通用 changed，每次重新生成全部预设、reset 基线和三套隔离配置，还向资源列表广播“预设改变”。新增只改选择的路径：保留不可变 JSON 对象数组，按需更新顶层、reset 和当前工具 profile 的 selected，再序列化；真正参数、资源、组织、工具上下文和 restore 仍使对象缓存失效。选择只广播选中参数与选中预览，不广播单预设或目录变化。PaintCoreClient 对当前偏好复用已缓存执行目录，跨文档不同快照仍按传入数据提取验证。执行票据、资源检查与失败原子性保持不变。
