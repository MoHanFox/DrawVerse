# 颜色与笔刷参数共同发布链路调查（2026-10-26）

目标：定位吸色、色盘、大小、流量、不透明度变化后的共同阻塞，区分即时 setter、35ms 定时发布、GUI 接收方恢复、后台保存与色轮绘制。复用 opt-in `qt_brush_interaction_baseline`，不修改产品调度、通知、防抖、缓存或格式。

使用隔离配置：默认库及仓库已有用户笔刷配置副本（不提交资源或配置），真实 Main.qml/Windows 窗口，1/2/3 文档。分别观察快速连续与可触发定时发布的慢速连续变化；色盘及滑条通过真实窗口合成鼠标事件。记录 GUI 心跳、同步派发、完整发布与恢复 spans、接收方目录重建及最终值。心跳和方法计时不称为输入到显示时延。首次/预热及配置加载不混入连续样本。

因果检查：同一进程逐次增加接收文档；通过独立 spans 拆开 source snapshot、共享选择尝试和完整恢复，并用相同二进制的启动方式消融对照，确认是否仅颜色/单个参数变化就执行整库校验。默认库为规模对照。所有输出写新目录，不改用户配置。

验收：四类输入均实际改变状态；每段末值与实际 INI 相符；接收方颜色/参数与工具上下文正确；记录失败和 trace 溢出。提供可复现命令、源码路径、实测开销及未覆盖项。此次仅调查，不把发现热点等同于已经修复。

正式启动必须保留 `Main.qml` 的 `createInitialDocument=false`，经 DocumentManager 创建真实文档。它会 track 初始服务客户端；该对象不在可见文档列表中，但仍是广播接收方/磁盘写入者。历史基准 `createInitialDocument=true` 把这个客户端直接当作首个文档，作为独立消融对照，不能代表正常单文档路径。runner 的 `--adopt-initial` 明确选择该对照。

测量期间不查询/同步 INI，待心跳与 trace 场景区间结束后再验证实际保存。QSettings 读取可能与后台写入相互等待，不能将观察器造成的停顿归因产品。跨客户端颜色按既有 HexArgb 的8位通道精度比较，不能将 HSV QColor 的内部精度差异当作同步失败。
