# 分组导入的资源发布顺序

2026-10-17，接目标库原子内存合并。ImageBundle新增import_into_catalog_persisted：先在私有候选目录完成完整合并和资源预算/身份/深度检查，再把包内所有内容寻址PNG与来源批次写入ResourceStore，最后检查取消并采用候选目录。失败不返回半目录，不改变当前选择、revision、原组织或预设Arc；非法目标/冲突在写文件前拒绝。

沿用既有资源和来源文件的临时文件+sync_all+不覆盖发布，以及已有文件的哈希验证；共享原ABR、当前/基线PNG和记录字节保持。一次包发布不能被描述为整个文件夹的原子重命名：磁盘失败或取消可能留下已验证、未被目录引用的内容寻址缓存。它们不是半导入的笔刷，不在失败时删除公共文件，避免误删另一个文档/进程已采用的同哈希资源。临时文件由既有RAII机制清理，缓存继续服从现有文件数/字节预算；独立安全GC不是本阶段能力。

这是现有共享不可变资源库的提交顺序，不引入并行的私有导入资源目录或新保存格式。此API不自行保存Qt偏好/目录文件；调用者只有成功后才能发布对应state20。原生后续应将此阶段和准备票据采用串联，保持源引用的准确捕获；Qt完整交接/重置基准仍待接。当前旧原生保护不解除，无ABI/state/VBR版本变化。

验证真实程序/图片包与三图片/ABR来源的新目录落盘、完整分组状态从全新ResourceStore重开及真实像素/载色/历史；重复/错误位置/预算/取消拒绝不写文件；已存在哈希冲突、PNG发布后来源发布故障保持旧目录和既有文件、不留下临时文件；失败后的修复与重试成功，复用合法共享文件。Windows必要回归/Release/ABI和旧Qt，硬件手感用户验收。
