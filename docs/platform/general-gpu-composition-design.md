# 通用 GPU 合成与即时编辑显示设计

日期：2026-10-28。状态：G0–G2纵向交付，G3有限范围实现、性能及完整回归部分完成；G4栅格支持矩阵已完成根混合/固定蒙版、隔离/穿透组、有效祖先蒙版、完整剪贴与Dissolve；矩阵外明确CPU；G5交付Windows/D3D11支持范围默认接入、多窗口/DPI/配额与注入故障恢复，真实驱动故障及其他硬件仍未测。初稿依据 `develop` 的 `4dba287`；本次实际起点为 `General-purpose-GPU-synthesis` / `d13e62b`，准确二进制与工作区证据见验收各阶段记录。不固定历史分支或ABI版本。

实施提示词：[开发任务入口](../planning/general-gpu-composition-prompt.md)。验收与阶段记录：[验收计划](../validations/platform/general-gpu-composition-validation.md)。当前已实现范围仍以 [GPU 加速入口](gpu-acceleration-design.md)及原专项验收为准。

## 1. 目标与范围

保留 CPU 兼容能力，在能力和资源允许时默认使用通用 GPU 图层合成。目标是绘画、移动、自由变换在常见及复杂图层栈中稳定响应，避免专项三图预览资格不同造成体验突变。

本方案不要求同时重写笔刷算法、历史、文档格式、输入系统或 Qt/QML 工作区。现有 `paint-ops` / `paint-gpu` 数值执行器继续服务计算任务；通用显示合成不通过返回 CPU 像素的算子接口逐帧往返。新增架构不等于已支持 GPU 绘画、ICC/HDR 或全部图层组合。

首帧响应是独立交付目标：进入移动/变换、首次有效位移、连续更新、释放确认分别测量。资源准备完后的稳定拖动不能替代进入即拖；合成器完成也不能自动认定首帧问题已解决。

## 3. 职责与依赖

| 所有者 | 必须负责 | 禁止承担 |
| --- | --- | --- |
| `paint-core` | CPU 权威文档、笔刷执行、不可变瓦片身份、事务、历史、最终编辑提交 | Qt/GPU 设备、窗口、显存对象 |
| `paint-render` | CPU 参考/后备；从快照生成与设备无关的合成计划和依赖描述 | 修改文档；包含 Qt/RHI 类型 |
| `paint-task` / 文档 Actor | 有界调度、准备、取消、结果发布与顺序 | 等待 GUI/渲染线程完成后才处理高频输入 |
| `paint-ffi` | 计划/瓦片传输、版本能力、句柄租约、容量/身份校验 | 把 GPU 指针、Rust 布局或 Qt 对象传给调用方 |
| Qt worker / 客户端 | 异步读取小计划与必要瓦片、构造不可变显示包、接纳身份、反馈错误 | GUI 线程冷页读取、整图合成、逐帧整库序列化 |
| Qt 窗口渲染生命周期内的合成执行器 | GPU 资源、上传、合成通道、缓存/显存预算、直接显示、设备恢复 | 文档真值、历史提交、独立判定业务组/蒙版语义 |
| QML / Canvas 输入 | 输入映射、工具交互、局部几何反馈、显示状态 | 像素算法、重复维护图层合成规则 |
| `paint-ops` / `paint-gpu` | 已有 CPU/GPU 数值算子及后备 | 强制实时显示每步返回 `Vec<Rgba>` |

推荐依赖：`paint-core` → 被 `paint-render` 读取 → 经 `paint-ffi` 发布 → Qt 客户端 → 窗口 GPU 执行器。CPU Renderer 保留并行可选入口。先在现有 crate 内建立明确模块边界，只有实际依赖或编译隔离需要时才新增 crate。不要为目录整齐迁移整个会话引擎。

硬规则：同一有效快照与同一显示请求的 CPU/GPU 语义一致；不支持必须显式后备；缓存不拥有文档修改权；显示失败不得改写像素或产生历史。

## 4. 设备与 Qt 接入决定

首选在所属 Qt 窗口的渲染设备上执行显示合成，结果直接交给同一场景图。Rust 保持计划与语义，Qt 执行数据驱动的渲染通道。C++ 的 shader/通道实现是渲染后端，不能增长为另一套文档编辑内核。

正常显示禁止采用“Rust wgpu 合成 → CPU 整帧读回 → QImage → Qt 重新上传”作为最终快速路径。读回可用于测试、诊断截图或明确需要 CPU 像素的作业，不属于每帧显示必经步骤。

G0 必须先完成可运行技术验证，再确定采用的 Qt 节点、离屏通道和 RHI 接入 API：

- 对照项目声明的 Qt 6.5+ 与本机 Qt 6.8.3，核查 API/模块可用性。不能默默依赖更高版本接口；若确需提高最低版本，先记录理由和影响，再同步构建与 README。
- 证明能在同一窗口设备进行多通道离屏合成、采样前一通道并直接显示，处理透明像素和浮点格式；单张 QSG 纹理贴图不算证明。
- 私有 API 如不可避免，只允许隔离在小型后端适配层，明确 Qt 版本约束、构建检查和场景图失效处理。
- 软件场景图或必要格式/能力不足时进入 CPU 路径。设备支持以实际窗口查询为准，不能由 wgpu 设备可用推断。
- 原生设备互操作是备选研究方向，必须证明设备归属、同步、格式、跨窗口和恢复成本；不预先承诺 wgpu 与 Qt 可零拷贝互通。

G0 的渲染试验、失败证据和最终决定写入验收记录。若首选路线不可行，保留 CPU 默认路径并提交替代方案；不能把逐帧读回方案标记为通用 GPU 直显完成。

## 5. 合成计划与跨边界数据

新增与设备无关的不可变计划，不强迫现有 `Renderer::render -> RenderFrame` 携带 GPU 句柄。旧 CPU ABI 与 Renderer 继续有效。

计划至少描述：文档/generation、已发布 revision、publication/计划身份、视图与请求身份；有序图层/组和中间表面；源瓦片及隐式默认像素；偏移、可见性、opacity/fill、混合模式；蒙版/剪贴依赖；合成范围、采样与 LOD；需要的能力与预算估算。具体字段、编号和布局在 G1 按真实实现确定，不在提案中预占 ABI 常量。

可用计划操作包括源采样、蒙版覆盖、图层混合、隔离组、穿透组前后结果混合、剪贴约束和最终显示转换。计划生成器负责解释层级，执行器根据明确操作执行，不在 Qt 根据不完整元数据重新猜测规则。

跨 ABI 的读取必须满足：

- 能力协商、结构 size/version、长度上限和调用方缓冲区约定；只做向后兼容增量时按现有政策升 minor，破坏性修改升 major；Rust 定义生成头，四类消费者验证。
- 获取有界只读计划/快照租约；按该身份读取计划及瓦片。同一包不能混用不同 publication；无效、过期和关闭请求显式返回状态。
- 瓦片键使用文档 generation、不可变内容身份、格式等必要字段；裸地址、layer ID 或只有 revision 不足以证明像素一致。相同 layer 的 COW 新瓦片必须失效旧键。
- 读取、暂存和上传队列分别有字节预算与并发上限；消费者释放包/租约后解除 pin。发布取消、窗口关闭和文档销毁必须释放，不能无限钉住 PagePool。
- 优先传未变化的身份与变更瓦片。CPU 到 GPU 的必要初次/增量上传是允许成本；禁止每帧复制整文档或 PNG 编解码作为常规协议。
- 所有冷页读、解码及大块打包在后台完成；GUI 与渲染线程只接纳已准备的有界数据。不得让渲染线程调用会触发磁盘读的 FFI。

## 6. 像素语义与支持范围

CPU 文档仍使用现有线性预乘 RGBA 浮点政策。中间合成不能提前转成 sRGB8；最终显示沿用现有显示转换、透明规则和棋盘格叠加顺序。GPU 内部纹理格式必须通过能力和误差验证，不能为加速悄悄降为 RGBA8。若选择半精度，必须有单独误差依据与不支持时后备；不凭“看不出差别”放行。

必须复用项目语义：隐式白底/显式透明覆盖、画布外裁剪、负偏移、组顺序与隔离/穿透、opacity 与 fill、反向隐藏量蒙版及其显隐/密度/链接、剪贴链、混合模式和 Dissolve 的位置/种子规则。先从核心代码提取/确认，再编写对照，不能套用其他编辑器的蒙版颜色规则。

LOD 必须保持现有“先按原语义合成，再降采样”的参考定义。逐层 mip 后混合通常不等价，尤其涉及蒙版、非线性混合和透明边缘。任何预合成缓存、层级采样或近似代理必须明确精确/近似资格与误差，不能继承已有 2048 代理就宣称任意放大精确。

按阶段公开支持矩阵：图层类型、组、蒙版、剪贴、混合模式、选区编辑、显示后端和格式。初期支持普通 Normal 栅格栈及自身蒙版，随后覆盖隔离/穿透组、有效祖先与固定蒙版、剪贴和项目已有混合模式。没有测过的组合保持 unsupported/CPU，不静默丢掉操作。

现有三图 resident 路径继续可用，迁移时每种操作只有一个明确的画面所有者；新通用路径未通过对应验收前不删除旧路径。

## 7. 缓存、增量、预算与调度

GPU 缓存按窗口设备/设备 epoch 隔离，分别统计源瓦片、组/前缀中间表面、合成目标、上传暂存与在途资源。CPU 已释放不代表 GPU 在途引用已结束；销毁与回收遵守渲染设备同步，失败后增加 epoch 并拒绝旧资源。

计划身份变化不自动意味着所有纹理变化。重排/可见性/混合/蒙版变更通过依赖使受影响区域和缓存失效；纯位移、视口导航和控制点变化尽量只改几何/采样参数。组/剪贴的依赖闭包必须纳入脏区，缺乏证明时扩大重算范围。

预算在 G0 按测试硬件和既有内存/暂存设置制定并记录：至少限制显存缓存、上传暂存、在途包、计划节点、源瓦片、输出像素和单帧工作量。估算采用实际格式/对齐/中间表面大小，不能把像素预算当总显存预算。超限先有界淘汰/切块或整帧后备，不阻塞主线程等待空闲。

后备首版以完整视图一致性为单位。局部 CPU 子树后备只有在隔离闭包/背景依赖与 alpha 被证明正确时采用；不能把穿透组或剪贴链任意切开混合。

GPU 主视图正常工作时，不要求后台为每个显示状态再生成一张完整 CPU 主视图帧作为镜像。CPU 文档仍持续接纳真实编辑，CPU 合成按后备、导出、取样/缩略图等实际请求调度；导航和缩略图维持独立有界、低优先级更新。否则虽然直接显示已接入，CPU 合成瓶颈仍会占用后台队列。小型参考对照属于验证路径，默认关闭。

调度沿用输入优先、主画布优先于导航、协作取消与背压。显示请求可合并为最新可用状态；不得丢弃/重排原始笔采样、Begin/End/Cancel 或历史命令。持续输入时允许符合既有 revision 下限的有序显示，避免“永远等最新”导致饥饿。

## 8. 移动与自由变换首帧协议

进入操作之前：根据当前目标、内容 revision、选区和视图密度准备可复用计划/源瓦片；目标变化立即失效，后台准备不能抢占高优先级绘画。Ctrl 拾取不同目标必须由核心确认，不能为了首帧速度猜测目标。

进入时：记录请求身份和待确认状态，优先复用已经有效的文档纹理。核心确认目标/源后，本地显示几何使用最新绝对输入，不能重放旧回包的位移。变换几何校验在核心仍有效，拒绝的候选保持上个合法状态；局部预测与权威 revision 分开标识，不能冒充文档已提交。

拖动时：已就绪的 GPU 源只改矩阵、网格和必要遮罩参数，触发下一次可用场景图更新；不等待 16ms 命令合并计时器或每次 Actor 回执后才移动。核心输入顺序与局部历史保持。背景相关组/混合由通用计划按依赖重新合成，不能简单整体挪动最终画面。

冷资源：目标是最早显示可验证的正确结果，明确记录等待原因。若现有源不可用，保留最后正确帧；选择框/光标即时变化单独计量，不算内容首响应。不承诺冷盘/驱动冷编译零延迟，也不使用长期模糊代理掩盖准备耗时。

释放/取消：沿用且扩展现有关闭屏障。当前操作结束后，保持最后正确预览，直到同 generation、同主视图/请求上下文的最终权威 revision 已被渲染节点采用，再一次交接。概览、无关 frameSwapped、旧请求或只有元数据完成不满足条件。快释放、取消、Undo/Redo、切文档与关闭均须验证。

## 9. CPU 兼容、最终像素与故障恢复

启动能力不足、用户强制 CPU、不支持组合、预算不足、GPU 初始化/执行/设备失败均有明确后备原因。后备使用对应有效快照和相同视图；异步准备时保留最后正确画面，接纳 CPU 帧也遵守 generation/request/revision 与操作关闭屏障。

GPU 缓存可全部丢弃并由 CPU 文档重建。设备失败不重放已提交编辑，不提交 GPU 预览像素，不改变历史、不丢笔；重试有界且不得每帧反复初始化。渲染后备与 Rust wgpu 计算设备选择分开表达，沿用现有性能设置入口的实际语义。

最终移动/变换/液化结果暂沿用核心全精度物化与单次历史事务；导出、吸色、缩略图和保存继续使用原权威路径，逐项验证后才考虑迁移。GPU 显示与 CPU 导出必须对照；截图不是文档数据。以后采用 GPU 最终计算时，也必须通过明确的读回/校验与原子事务进入 CPU 文档，不能留下只存在显存中的已提交作品。

## 10. 实施阶段与退出条件

| 阶段 | 实际交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| G0：基线与后端验证 | 移动/变换首帧分段基线；同 Qt 设备多通道直显试验；设备/API/精度/预算决定 | 真窗口证据、无逐帧读回；未决项和测量口径明确 |

## 11. 验收口径与工程边界

## 12. G0 技术决定（2026-10-27）

采用所属 QQuickWindow 的 QRhi 作为下一阶段显示后端研究路线。`qt_gpu_composition_probe` 已在真实 D3D11 窗口用同一 QRhi/命令缓冲执行三通道，再由 QSGTexture 直接采样最终纹理；没有经 CPU 读回生成显示 QImage。这是有限固定夹具的可行性证据，不能当作实际文档增量合成完成。

- 项目最低 Qt 6.5 保持。试验显式 opt-in，配置门槛为 Qt 6.6 / GuiPrivate；只在本机 Qt 6.8.3 MSVC x64 构建运行。6.5 不参与该试验，6.6/6.7 未验证。当地 `rhi/qrhi.h` 明示 limited compatibility guarantees；G1 后端适配必须隔离此依赖并逐 SDK 验证，不能宣称已有跨版本稳定 ABI。
- 接入点为渲染线程 `beforeRendering`，在窗口主通道开始前记录离屏通道；读取 RhiResource、RhiRedirectCommandBuffer，原生窗口可取 swapchain 当前命令缓冲。结果通过自定义 QSGTexture::rhiTexture 供同窗口场景图使用。试验着色器明确只支持 D3D11 坐标约定；不从 qsb 含其他目标推断已支持其他 API。
- 先保留 RGBA32F 中间纹理、RGBA8 最终显示。64² 全像素线性最大误差 5.96046448e-8，RGBA8 和真实窗口 RGB 最大误差各1；既定门槛未放宽。未批准 RGBA16F、逐层 mip、HDR、任意 LOD 或2048代理作为精确合成。CPU 对照按 Rust `display_pixel` 的线性预乘/解预乘/sRGB编码/再预乘，以及 mask alpha 表示隐藏量的规则编写；G2 仍须直接与 CPU Renderer 的文档夹具比较。
- QRhi 和所有纹理归窗口节点所有。第二窗口分配不同 QRhi/资源；关闭持久图形后 hide/releaseResources 再显示，原节点释放、新节点重新上传。节点记录设备身份变化即拒绝旧资源。这里验证的是场景图失效重建，不是 D3D DeviceRemoved、TDR 或显存压力恢复。
- 硬预算、误差冻结与原始证据见验收第9–10节。试验只接纳固定64²夹具；格式/分配/命令缓冲失败使试验显式失败。软件场景图使用独立 CPU 参考图。产品仍走现有 CPU/常驻预览路径；产品级自动故障后备、资源计账与重试由 G1/G2/G5 实现，不能由实验失败处理推断已完成。

不采用独立 wgpu 离屏输出或逐帧读回方案。当前证据支持继续 G1，不需要先更改文档格式或核心真值。G1 必须形成不可变计划/有界瓦片租约的可运行传输链，再由 G2 接入实际画布；G3 必须单独解决首位移、立即释放与最终主视图交接，不能拿当前约11ms的稳定移动替代首帧目标。

## 13. G1 实施决定（2026-10-27）

`paint-render::composition` 编译原始分辨率不可变源与节点描述，构造时不读像素；CPU解释器是传输语义参考。初始支持根Normal栅格与链接自身蒙版，保留透明、opacity/fill、偏移、隐式白与显式透明覆盖。复杂组合完整拒绝，默认显示继续原路径。未建立GPU资源或修改paint-ops/paint-gpu数值任务。

ABI1.81使用独立version1能力，发布描述和每次一块64KiB小端线性预乘RGBA32F；调用方worker可触发原PagePool读取，GUI/渲染线程不读取。稳定内容ID通过最多8192项Weak私有索引识别Arc内容，COW失效，淘汰只造成重新上传；无原生地址进入协议。组/穿透/剪贴依赖仍是后续完整迁移范围。

独立显示邮箱与业务FIFO分开，最多两租约/会话。generation、revision、view、request、epoch、lease、publication联合拒绝旧结果；请求不占笔采样sequence。取消、设备逻辑epoch变化、新文档与关闭撤销租约，最后缓冲复制与取消有明确锁内线性化顺序，冷IO在锁外执行。当前epoch仍由调用方提供，实际窗口设备绑定与故障恢复由G2/G5实现。

预算从G0候选调整为每租约256MiB源引用/8MiB保守元数据（4K原始瓦片已需256MiB），进程512MiB计划/16MiB读取暂存，构造前预检与原子预留；在途持有者延长预算至最后释放。Qt验证消费者另限64节点/64瓦片/4MiB像素/128KiB元数据，CPU像素解释在worker完成。真实窗口两后端与CPU全图一致，只证明G1纵向传输；不得把这一CPU QImage上传称为通用GPU合成。门禁与保留失败见验收第12节。

## 14. G2 实施决定（2026-10-27）

实际Canvas以`DRAWVERSE_GPU_COMPOSITION=1`显式启用窗口QRhi后端；默认保持原显示。Qt≥6.6时将GuiPrivate依赖隔离在CompositionNode适配层，目前仅接受D3D11/RGBA32F；Qt6.5仍可构建原CPU路径，未做该SDK实际编译。G1 packet由BackendWorker有界读取，GUI发布不可变引用；所有源atlas、原分辨率双线性目标、RGBA8显示目标与上传暂存属于本窗口，GPU结果直接由QSGTexture采样。

先原分辨率按Normal/链接自身蒙版语义合成，再沿CPU相位做power-of-two LOD/有效边界平均与显示转换。只变瓦片重合成其影响区域，配置改变重合成完整闭包；源ID复用和合成脏区分别统计。普通活动笔触发布CPU候选的不可变源，不改变最终提交或单历史。G2仍并行准备原CPU视口，不以此阶段宣称已消除CPU合成成本或改善输入延迟。

消费者64节点/1024源块/64MiB包，原文档及视口各≤4,194,304像素、边长≤4096、LOD≤6，超出明确CPU后备；4096²原图不缩成代理冒充精确支持。当前纹理payload每节点≤256MiB，进程对延迟销毁按最大payload×(FramesInFlight+2)保守预留≤2GiB，上传共享源至slot复用才释放；驱动隐藏分配未量测。设备身份/epoch变化拒绝旧资源；初始化/上传失败停用该epoch并继续CPU，真实设备恢复/压力与支持范围默认启用仍待G5。准确结果与失败见验收第13–14节，G3首位移仍未通过。

## 15. G3 实施决定（2026-10-27）

根Normal移动在BEGIN确认实际目标后直接修改不可变源包的偏移，链接自身蒙版同移；确认前保存最新绝对输入。自由变换首批限无选区、无自身蒙版的单个根Normal栅格，保留原始瓦片；Rust纯几何ABI1.82生成与最终CPU同源的Warp网格及double逆矩阵，Qt只处理有界几何，不读取冷页或计算整图CPU像素。正常显示不读回，paint-ops/paint-gpu数值任务保持。

源revision、核心业务sequence与本地geometrySequence分开；确认后本地绝对输入直接发布，不等待16ms业务合并或每次Actor回执。BEGIN/结束屏障额外启用最多256次、1ms异步元数据检查，原16ms轮询仍作恢复，无阻塞等待。相同几何不重复推进本地序号，旧metadata不能覆盖更新输入；业务采样与历史仍由原FIFO及核心提交。

FP32固定功能Warp边界不能满足最近邻硬边精度。D3D11变换因此额外协商DoublePrecisionFloatShaderOps与ExtendedDoublesShaderInstructions，用同窗口double采样、显式CPU同源三角归属/顺序覆盖，RGBA32F源/中间和先合成再LOD保持。六种插值均复用核心核函数与钳制语义。double不足、选区、自身蒙版、几何/显存/工作预算不足均显式CPU；G2 Normal不要求double。Qt的qsb生成SPIR-V/DXBC，沿现有构建期预编译开关；检查实际嵌入shader及224字节uniform布局。此限定不代表其他API/硬件已支持。

Warp临时原分辨率纹理、最多145²顶点/41,472三角形、≤2MiB实例缓冲、≤33,554,432裁剪包围像素工作，均纳入预算；每不可变几何计512KiB、进程32MiB，小表/缓冲保守预留4MiB。单节点256MiB与进程2GiB含在途预留保持，分配不通过继续CPU，不降低网格或换2048代理冒充精确。

立即释放提交最新输入，取消立即恢复原几何；保留源直到对应主Canvas实际采用同generation/epoch的最终权威revision。GPU证明来自同节点afterRendering已记录的最终包，CPU证明来自主imageNode实际采用的最终图像；概览或任意frameSwapped不触发交接。切换客户端也更新设备逻辑epoch，跨文档同generation不放行旧回执。传输失败可由对应CPU主节点完成交接，不修改文档或重复历史。节点采用/命令提交/对应frameSwapped均不是物理屏幕显示。

窗口源准备时创建并缓存普通线性、显示、精确变换及Warp四种兼容管线，几何更新不再重建pipeline；创建失败按普通显示/精确变换能力分别后备。隐藏期间到达的最终CPU图像不能直接作为已显示证明，恢复可见时主动刷新并恢复视口请求，由对应主节点完成采用交接。当前功能检查点与保留失败见验收第16节；Warp性能门槛及最终版本配对尚未完成，默认OFF。

## 16. G3 热点与观测续接（2026-10-27）

保留double坐标/权重、CPU同序f32累加、原图及145²网格预算。整数源地址直接算术右移求64瓦片索引；双三次每轴四权重及邻域最多四槽位复用，固定循环在构建期展开。Qt控制轮廓每次绘制快照16点，在控制行/列结点使用等价单轴Catmull求值，八条49点曲线和其他位置二维求值保持。不能由静态指令数量或最近整帧GPU时间推断首输入响应，必须重做同版OFF/ON配对。

沿既有有界InteractionTrace增加CPU命令准备及最近已完成整帧GPU时间，窗口时间戳仅在显式诊断时启用；无当前geometry或物理屏幕完成的因果承诺。正确性抓图必须持有QQuickItemGrabResult至GUI线程收到ready()，image()非空不能证明渲染线程已结束对结果对象的访问；抓图仍置于性能计时区间之外。转储、旧失败、修复后正确性及准确版本量测见验收第17节。

完整变换通道可在源revision/generation/设备epoch、节点/瓦片描述、来源边界、视口/LOD与Warp拓扑完全相同时保留页表、采样轴、参数缓冲及SRB，仅更新精确uniform和原分辨率网格。仅显示通道的上一帧不能被误作完整通道缓存；依赖/尺寸/拓扑改变重新准备，所有资源仍属原窗口及原预算。相同几何的元数据发布可保留完整缓存；本地几何序号改变才上传网格/参数，没有跨窗口资源共享或新增CPU像素工作。

编辑源计划已在预算内包含完整可见图层瓦片，主视口resize可在GUI复制小包并更新Qt显示投影region/pixels/LOD，本地序号递增，Rust源/租约key不变。新视口超原输出或LOD预算明确CPU；隐藏禁用仍保留源待最终主节点证明。节点必须采用对应投影和几何，不能用先到的CPU新帧或旧request的存在代替。

## 17. G4 首批组合迁移冻结（2026-10-27）

从51a108a继续，用户明确开始G4；G3未过门槛和旧失败保持，不改写为通过。首批纵向只扩展根栅格固定自身蒙版与Normal之外除Dissolve/PassThrough的25种混合模式。整栈仍拒绝组/剪贴/置入图，不能切开依赖闭包。混合严格复用核心线性预乘公式，蒙版按原坐标与反向隐藏量采样，先合成后LOD；蒙版链接只决定移动时是否一起平移。移动更新节点偏移后重新合成背景依赖，不能移动最终合成图。自由变换非Normal目标暂走原CPU，防止原精确变换shader把混合模式隐式当Normal。

版本1计划以新增可协商能力FIXED_MASK/BLEND_MODES描述扩展，ABI minor加一、结构布局不变。节点reserved在对应能力下解释为低32位blend ID、高位32固定蒙版标志；旧请求仅features=7继续得到旧支持范围与reserved=0，不会收到不能解释的扩展。其他位必须0。没有新增源、中间表面或GPU指针，原预算、取消、窗口epoch及最终CPU提交保持。Dissolve的64位位置hash尚未迁移，明确CPU而不近似随机数。

## 18. G4组与祖先蒙版续接冻结（2026-10-28）

从89e20f6的首批支持继续。隔离组先在透明中间结果合成子层，再依自身蒙版/opacity/fill/混合与父背景合成；穿透组必须保留父背景before，以其为初始合成子层得到after，再按原核心的蒙版×opacity×fill插值before→after。嵌套隔离/穿透不互相展平；有效祖先蒙版在对应组边界生效，固定蒙版移动时留在原坐标。剪贴/Dissolve/置入图在完整迁移前仍整视图CPU。

Rust计划生成器编译有界顺序操作（清空、复制、栅格混合、组表面混合、穿透前后插值），Qt按操作执行，不从不完整层级猜测组语义。操作只引用本计划节点索引和抽象中间表面编号，版本/能力协商后读取；数据不含原生指针。按组深度保守预留中间表面，最大16级；不提高单节点256MiB/进程2GiB含在途预算，预算不足整视图CPU。先全分辨率组闭包合成再LOD，正常显示不读回。组内复杂自由变换继续CPU，移动可在确认目标后复用原源和组操作，仅更新必要节点几何。

ABI1.85/可选GROUPS=32实现该操作流，原version1/info/node布局保持；操作32字节，最多4×节点+1。每级复用一对RGBA32F表面，最多34表面，按实际有效组深度分配；隐藏祖先不pin/read子源，也不生成子操作。穿透插值直接复用核心Pixel::mix的线性预乘公式与相同值跳过分支，不能以隔离组source-over替代。Qt同一原窗口QRhi执行全部通道，显示轴仍采样最终原分辨率结果，调试读回只有正确性观察者显式请求时开启。

组移动从明确parent索引扩展实际所选子树，平移普通后代和随所属节点移动的链接蒙版；固定蒙版保持原坐标，移动子层不平移祖先蒙版。组节点本身offset始终0。目标确认后仍用最新绝对输入发布独立geometrySequence，不等待后续Actor回执；CPU最终事务与对应主视图采用交接保持。包含组的自由变换明确关闭这条几何路径并采用完整CPU结果，后续按组合迁移，不跳过背景或祖先。

## 19. G4剪贴与Dissolve续接冻结与实现（2026-10-28）

在组检查点之后继续完整栅格剪贴闭包与Dissolve，能力仍显式协商。不剪开剪贴链：普通基底先取得带自身蒙版的原始源，依序按核心的保留基底alpha规则施加剪贴层，再施加基底opacity/fill及混合；穿透基底保留父背景before，取得after及从透明合成的intrinsic alpha覆盖，剪贴影响按原coverage限定，最后按基底蒙版与权重插值。嵌套穿透/隔离剪贴不能展平，不支持或操作/表面预算不足整体CPU。为原始源/覆盖保留有界额外表面，原GPU字节预算不提高；重复intrinsic计算须在每次追加操作前检查硬上限，避免嵌套递归指数增长。

Dissolve使用核心文档坐标、完整u32种子和精确64位乘法/hash语义。D3D11可用成对u32和16位部分乘积实现64位模乘；随机阈值采用f32 alpha的精确整数边界，不能用低精度随机float比较或静默替代Normal。仅最终合成结果参与LOD。剪贴与Dissolve的复杂自由变换可保留明确CPU；不改变最终核心提交和文档格式。

ABI1.86新增DISSOLVE64/CLIPPING128，节点bit49剪贴、操作原reserved分别携带完整种子及可选coverage索引+1，既有布局不变。剪贴计划按可见组深度为每层保守预留原双表面及三个额外槽，最多85个RGBA32F表面、16×节点+1操作，每次追加先检查；原256MiB节点/2GiB含在途GPU预算保持。Qt为coverage绑定独立纹理，精确变换shader可忽略这个额外绑定，统一224字节uniform保持。

计划先生成纯元数据与完整操作，再标记实际读取的栅格/蒙版并pin源；隐藏基底的剪贴层不会因为自身visible而被读取。无剪贴仍沿原组/平面操作预算。Dissolve采用16位部分积的64位模乘与ceil(alpha×2^32)整数阈值，无需FP64能力，显式float随机阈值反例和真实窗口对照作为门禁。剪贴移动继续采用既有绝对几何与主视图交接；复杂剪贴/Dissolve自由变换明确整CPU闭包。

Dissolve上游alpha舍入同样属于随机语义：实际D3D11反例证明单次FMA收缩会把保留像素变成透明，故影响alpha的运算使用GLSL precise，维持核心逐次f32舍入；不以颜色容差接受错误的随机保留决定。85个重开文档的完整像素真值与失败证据见验收第20节。

## 20. G5稳定、恢复与默认接入冻结（2026-10-28）

从已提交推送的G4 d6d86b5继续，ABI1.86/state45/文档不变。支持范围在Qt≥6.6 QRhi适配构建且窗口D3D11/RGBA32F能力与原预算允许时默认启用；DRAWVERSE_GPU_COMPOSITION=0或无效值明确CPU，其他Qt显示API/软件保持CPU。数值计算设备设置与Qt显示设备独立，不扩大精确自由变换或置入图支持。混合菜单悬停预览属于未提交CPU显示，静态GPU计划必须暂时退让，不能覆盖该预览。
