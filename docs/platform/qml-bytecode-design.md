# 打包 QML 字节码

2026-10-22，处理首次面板创建时的 QML 解析停顿。原构建仅用 rcc 打包源码，复杂笔刷面板第一次加载还要解析自身和相对导入的控件。使用 Qt 的构建时字节码缓存，提前完成这部分工作；不改变控件创建时机、面板内容和交互方式。

## 构建与链接

`ui/CMakeLists.txt` 仍以同一份资源清单为输入，分离 QML 与图片/qmldir 等资源。QML 交给 `qt_add_qml_module`，只生成字节码，保留原始源码。内部打包 URI `qml` 加资源别名维持 `qrc:/qml/...` 地址；应用继续直接加载原 URL，不要求业务代码导入新模块。Theme 同时标记为 singleton，保留既有目录 qmldir。Qt 6.8 及以上显式使用 NO_GENERATE_EXTRA_QMLDIRS，不向现有子目录注入新的模块导入；更早版本沿用其原行为。不依赖已弃用的 Qt 策略或屏蔽诊断。

静态库中仅生成缓存不足以保证缓存被链接：直接 qrc 加载不会主动导入内部打包模块。`platform/UiResources.h` 同时初始化资源和生成的缓存注册，应用、源码预览宿主及三个完整UI测试入口使用同一个函数，防止链接器剔除缓存。构建图管理每个 QML 源码的字节码依赖；原资源更新依赖仍保留。

使用字节码而非完整类型化的 C++ 函数编译，保留现有上下文属性与运行时注册 C++ 类型的行为。Qt 版本随构建与分发运行库保持一致，框架原有校验与源码后备保留。无 ABI、核心 state、文件格式或 GPU 算子变化。

## 源码预览及验收边界

Qt Creator 独立预览宿主仍加载磁盘 file URL；内置缓存只注册 qrc URL，因此编辑、原子保存与错误后重建仍读取新源码。不要将正式程序改成扫描源码目录，也不要把预览运行时写入正式偏好。

验收直接遍历打包 QML，核对每个 URL 都有当前 Qt 接受的字节码，且原始资源文本逐字节等于源码；再检查真实界面、欢迎生命周期和两种后端的源码预览。首次面板加载对照交替使用相同文本的新临时源码目录与内置 URL，创建新引擎，复制文件在计时外；记录加载加创建时间，不断言机器相关阈值。该对照不是冷盘或端到端首次显示延迟。

预编译只消除解析/编译部分，仍需创建控件、准备图像和上传纹理，不能据此宣称 P1 或所有界面停顿完成。实际记录见 [验收](../validations/platform/qml-bytecode-validation.md)。
